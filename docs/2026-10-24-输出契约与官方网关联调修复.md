# 输出契约与官方网关联调修复（2026-10-24）

本次针对官方报告的11题全部 error、运行证据已验收但输出不合规范进行修复。原始材料目录保持用户整理后的结构。

## 确认的问题

0.4.3 使用原生 AgentRuntime，但把 SDK 的 task_id/status/output/metadata 四字段包装直接作为 HTTP 答卷。赛题要求最外层只保留对应题型字段，解包内部 answer 并不代表线上响应合格。旧验收缺少这一边界检查。

0.4.4 候选补上最外层转换后，通过合成模型响应的协议验收。随后用户提供了官方统一模型网关，真实模型测试进一步发现：C类程序附加的事实摘要与模型正文合计55次引用，超过新上限；将全文送入段落补丁修订导致180秒超时。该候选不作为交付版本。

## 最终实现

- 使用官方 AgentRuntime 原生实例、原生 health/solve 路由以及原生 OTLP 导出，不修改 SDK 源码。
- 八字段题目转换为 SDK 输入；成功响应转回严格题型 JSON。真实 SDK metadata 放响应头，失败和超时保留 SDK 状态及 metadata。
- 默认只检查约定的专用论文库位置；授权根内的绝对路径可定位，拒绝越界和符号链接。D类只增加当前题公开实验目录，不授权其他题。
- C正文4500字符、40次引用，E正文6000字符；包含空格和Markdown，参考文献节不计正文。复合引用按实例计数。
- C写作请求明确扣除程序事实摘要已占用的字数和引用额度；全局超限要求模型精简整稿，避免整篇使用段落补丁。补检保留后续写作审查时间。
- E写作失败保留证据并报告失败，不再拼接硬编码保底正文。

## 官方模型配置

用户指定的官方网关和 deepseek_v4 已保存到忽略的 .env.local；环境模板只保留官方地址、模型名和密钥占位符。生产镜像从运行时环境读取密钥，不内置密钥。测试仅向该网关发送合成问题和合成论文证据，不使用其他供应商模型。
