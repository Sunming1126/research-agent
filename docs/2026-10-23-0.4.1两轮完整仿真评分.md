## 失分复盘

### 1. 数字引用修订仍会失败

第一轮 C-01 初稿的上一句有数字及页码，下一句分析重复了 44.1% 和 36.6%，却未单独附页码。严格逐句校验拒绝提交；局部修订后，另一处比较句仍重复 44.1% 而无页码，再次失败，最终采用保底报告。真实失败原句已在 `additional-readback.json` 回放确认。

这是 Agent 的引用生成与修订覆盖问题，不能归因于题目或新 Key。后续应一次枚举所有违规数值句，要求模型引用当前台账的正确证据，修订后完整重查。不能简单删除页码检查或把上一句引文无条件继承给所有数字。

### 2. 通过自审仍不等于完整回答

C-01 第二轮通过自审但只覆盖 5/10 条复合事实；缺口包括双编码器中查询编码器的明确作用、RAG 参数化生成器与外部索引的组合、FiD 不同段落数比较、反思标记评价证据与输出的作用。C-03 第二轮遗漏 TriviaQA 及部分检索评测表述。两轮 C 类五篇参考文献均有效，主要缺口是机制和评测条件覆盖。

后续应按当前题目的比较维度建立“问题—机制—实验条件—局限”覆盖表，补检或明确未知，再做自审；不能将本地十条金标或特定论文答案写入 Agent。

### 3. Idea 需要落到具体资源和基准

E-01 第一轮虽然给出 GPU 小时和停止规则，但资源与数据规模的匹配不足；第二轮指定 TriviaQA 候选划分，却未明确选择条件，裁判判为部分支持。E-02 两轮都没有确定医学场景的命名基准与适配流程，第二轮动机也不充分。

后续应区分“拟采用的基准”“当前是否已取得”“取得失败时的替代条件”，写明可执行的选择决策；未知许可、样本数和现有算力继续如实标未知。可预注册资源假设和启动前核验步骤，不能为得分编造已取得数据或设备。

### 4. D 类分差主要受计时口径影响

两轮 D-02 的查询吞吐分别约 15,846、14,250 queries/s，Recall 和 MRR 一致；第二轮 D-01 运行时间更短，旧代理量表仍按与参考值的相对偏差扣分。保留这些原始扣分，不通过放宽容差、添加等待或重跑计时制造提升。正式能力需在赛事容器资源和新版 runner 下另验。

### 5. 模型裁判本身存在不一致

例如第一轮 C-03 判全部事实完整，同时建议补充部分关键表述；关于 DPR 检索准确率与 top-k 召回的解释，两轮也有差异。原始分照录，不作事后补分。Agent 自审和外部评分使用同系列模型，不能以“无严重错误记录”代替专家事实复核。
