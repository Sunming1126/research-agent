# 科研助手 Agent 0.4.0 升级与验证报告

本轮开始于 2026-10-22，跨日收尾于 2026-10-23。当前源码版本：0.4.0；提示词版本：20261022-v5。

本次围绕复杂问题的证据覆盖、预算稳定性与实验闭环实施升级。验证包含真实模型任务诊断、已核验证据的写作复测、公开算法子进程执行和工程回归。本文没有生成新的官方分数。

## 一、已经落地的改动

### 单题会话与模型预算

- `core/session.py` 管理单题截止时间、取消信号和阶段记录。单题排队时间计入期限；批量派题逐题建立独立会话。
- 默认单题时间调整为 180 秒。正式 D 类即使配置更长，也最多使用 180 秒；生成、自测、平台执行共用剩余时间。
- `GatewayLLM` 统一 SDK 与标准库 HTTP 通道的系统约束、thinking 参数、重试和记账。
- 收到响应后立即记录 usage，再检查完成状态和 JSON；截断与格式错误不会漏记。
- 无法确认消耗的请求记录为 `unknown_reserved`，使用保守预留，并与网关实测用量区分。
- 每次重试重新核验调用数、Token 和时间。提取阶段为后续写作、审查、修订保留额度。

取消检查发生在阶段边界、文档逐页处理和模型请求前后；已经发出的同步请求受剩余时间与请求超时上限约束。

### 检索与材料处理

- 八个独立子问题完整保留，查询解析与执行共用上限。
- 新增倒排表，减少每个查询对全部片段的重复扫描；保留原题、改写和独立子目标通道。
- 完整文件名可直接召回，即使正文没有包含文件名中的词；实际输出保留真实文件名。
- B 类先做限页候选筛选，再在时间允许时深入最多八篇授权候选全文。库大小按解析后的实际文件数判断。
- 明确 `exclude/uncertain` 的模型结果不会被高词法分覆盖；强命中只能触发有证据的再次语义核查。
- 修复否定排除理由误判、参考文献之后附录被丢弃，以及短页正文被当作重复页眉删除的问题。
- 候选补读后仍保留原始授权文件集合、缓存与最终材料哈希核验。

### 证据、综述与研究方案

- 新增 `evidence/`：保存方法、数据、指标、结果和局限的覆盖矩阵，并标记当前证据缺口。
- 原文摘录匹配之后，增加独立声明支持检查，区分本篇工作、相关工作与不确定来源。
- 无法确认的模型解释退回原文摘录，原始 quote 保持不变；展示摘录统一空白并转换论文内部参考编号。
- 缺少关键维度时定向补检，限制篇数、片段数、时间与预算；不把当前缺证据写成“整篇论文没有研究”。
- 模型在内部草稿使用 `[E:ev-编号]`，程序从台账生成最终论文编号和物理页码，减少模型自行填页码的错误。
- C/E 使用独立写作约束。C 聚焦综述与比较；E 聚焦假设、输入输出、互补、对照、消融、指标、预算与证伪。
- 写作和证据获取拆成独立阶段，可在材料哈希与题目一致时定向验证写作。
- 修订仍采用精确原句替换，修订后检查变更、已知问题及全篇覆盖；审查历史与原始草稿均保存。
- 数字检查按 Markdown 的软换行、列表与建议章节识别范围，区分拟议统计参数、停止阈值与论文实测数值。

### D 类完整源码闭环

1. 从当前题公开方法、协议和样例生成完整源码。
2. 保存完整模型回复、提取源码与每次尝试记录，不在本地修改算法。
3. 使用不继承网关凭据的独立标准库子进程自测。
4. D-01 检查预测与返回模型的一致性；D-02 检查配置覆盖、分组稳健选择、完整排名和 run/rank 一致性；D-05 检查任务守恒、服务量、服务端及时间约束。
5. 公开自测失败时，最多要求模型再生成一次完整源码。
6. 锁源后只调用当前官方客户端；正式请求发出后不换源码重跑。

子进程包含静态访问约束。Linux 下尝试启用资源与系统调用限制，实际能力随结果保存；当前 Windows 测试没有 Linux 系统调用隔离，不能冒充正式平台沙箱验收。公开自测也不能签发官方来源凭证或验证全部私有算法条件。

## 三、真实调用验证

本次是逐步开发诊断，共 14 项真实模型任务执行，以及 7 项写作阶段定向复测。后者部分复用先前真实草稿，仅新增语义审查/修订请求；都不是多轮完整竞赛。

### 任务诊断

| 案例 | 范围 | 结果与记录 |
|---|---|---|
| A-81 | 小样本、非随机分组下的因果判断 | 回答、澄清问题、Schema 与回读通过，6.19 秒 |
| B-81 | CNN 损坏、动作识别、缺失多模态三个目标 | 3/3 命中，准确率与召回率均为 1，41.23 秒 |
| B-82 | 视觉、基因调控、统计学习与检索的八目标 | 8/8 命中，准确率与召回率均为 1，45.58 秒 |
| C-81 | 五篇视觉相关论文的研究设计比较 | 早期先后发现页码、文内参考编号和软换行问题；修复后完成，原始失败保留 |
| E-81 | 低光/损坏视觉鲁棒性研究方案 | 独立完整执行曾首稿通过；后续写作复测用于检验预算与停止规则 |

同一草稿的模型复核出现过不同判断，且存在过度解读问题；本次保留了判断、依据与修订历史。`audit.ok=true` 不等于专家逐句确认。

## 四、验证中实际发现并修复的问题

1. 截断和非法 JSON 的 usage 漏记；现已先记账再解析。
2. 八个子查询只留下五个；现已统一数量约定。
3. 参考文献之后的附录不可检索；现已恢复正文状态。
4. `not explicitly excluded` 被误排；现已识别否定并保留结构化决策。
5. 短页正文被重复页眉逻辑删除；现已保留短页正文。
6. 生成综述时填写了台账不存在的页码；现由证据编号生成物理页码。
7. 原文摘录的 `[30]` 被当成提交引用；展示层转换文内编号，原始 quote 保持原样。
8. PDF 自动折行将带数值事实拆成“无引用”片段；现按 Markdown 语义处理软换行。
9. 设计参数、95% 置信区间和停止阈值被误判为论文实测；现追踪明确建议章节范围，论文归因数值仍需证据。
10. 综述共用 Idea 提示词后附加了不必要方案；现 C/E 分别组织写作。

原始失败、保底、原始草稿和独立复测均保留，未覆盖成“成功历史”。
