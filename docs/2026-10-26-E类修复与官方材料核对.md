# E 类排查与官方材料核对（2026-10-26）

本轮针对 E 类实际接口错误、修订流程与正式输出文件。保留 0.4.10 的 B/C/D 修复，不修改官方 SDK，不将 E 模型失败改成程序模板报告。最终区分接口硬检查与模型语义自审：已有完整模型稿通过硬检查时，保留自审未通过的真实记录并交付模型稿；没有完整稿或硬检查失败仍报错。线上 `eval-20261024-fee4379f` 的具体堆栈尚不可见；本地发现不能直接宣称就是该评测的唯一根因。

## 官方要求与实现

依据本地现行 `科研助手赛题材料/research-agent-spec.md` 的 Idea、提交检查及 c1-output-limits-v1 章节，`research-scoring-rules.md` 的 2026-10-24 C/E 更新，以及 `赛题一组委会确认清单-逐项回复-20261015(3).md`：

| 要求 | 实现与核验 |
|---|---|
| 直接接收八字段题目，使用官方 AgentRuntime | 保留原生 SDK，仅自有协议适配；SDK 源码哈希对照 base:1.1.1 |
| E 仅返回 case_id、path、markdown | 独立检查 HTTP 字段集合，不添加状态、评分或通用 output 包装 |
| 平台目录标识 | 运行时 RESEARCH_WORKSPACE_TEAM；不是报名队名或 TEAM_ID |
| JSON 与报告均实际落盘 | `/output/data/<workspace_team>/<case_id>.json` 与 `/output/data/expert/<case_id>-灵感Idea报告-<workspace_team>.md` |
| path 为相对路径，完整正文逐字一致 | `data/expert/...md`；HTTP、JSON、Markdown 回读相等 |
| 正文至少 800、最多 6000 字符 | 上限包含空格、标点和 Markdown；参考文献节不计入；建议 1800～3200 |
| 真实论文引用与完整 PDF 文件名 | 证据来自授权 PDF 连续原文，引用用台账生成；结尾 `## 参考文献` |
| 方案依据、设计与验证闭环 | 提示与审查覆盖指标口径、接口冲突/量化回退、消融、资源与证伪；仅属于本地质量控制，不能代替官方评分 |
| 模拟观察与论文实测分开 | 写作、审查及局部修订均保留本题输入和约束 |
| 不得程序扩写 E 报告 | 仍由官方模型生成并修订；无 E 模板回退 |
| 单题 180 秒 | 内部 170 秒，E 各阶段保留写作、修订、落盘和 SDK 导出时间 |

## 已复现问题与修复

1. **最终引用校验才发现错误，导致 HTTP 500。** 原版 0.4.10 的官方 API 实测 E-01 中，模型生成参数列表 `[2,5,8]`。前置只检查单个编号，最终检查把组合标记作为引用，抛出 `body citations and references differ`。已统一组合引用规则；合法 `[1,2]` 会生成两篇参考文献，非法标记进入模型修订。
2. **数学闭区间提示不准确，修订改错位置。** 候选版模型输出 `s ∈ [0,1]`，错误信息却写成正文不存在的 `[0, p.]`。现返回实际标记及所在行，集中列出所有错误；闭区间提示用全角方括号保存数学含义，不编造参考文献。
3. **格式修订挤掉内容修订。** E 最多三轮生成/修订机会、最多两次语义审查；允许一次格式修订后再做一次内容修订。仍受整体时间及 Token 预算约束。
4. **审查有问题却放行。** 模型曾返回 `ok=true` 且 `issues` 非空。程序现保留原始审查，但有效状态判为未通过，进入修订；不能把矛盾结果算成功审查。
5. **多问题定位不完整。** 审查引用的原句可能省略 Markdown 粗体，导致部分问题定位失败，而之前只发送定位成功的段落。现忽略排版差异；任何问题无法定位时传递完整正文，不静默遗漏。
6. **时间及上下文不足。** E 原先未使用 C 的阶段截止设置，且做了额外表格网格解析。现 E 保留完整 PDF 文本和页码但不重建表格网格，为后续阶段预留时间；修订同时接收题面观察和约束。
7. **审查边界。** 人工抽查发现过代码可用性、数据规模无依据的扩写，也发现模型把拟议参数、数据集仅命名、统计解释错误判为需要论文证明。已针对实际生效的提示收紧边界；模型审查仍可能漏判或误判，不能视为专家核验。
8. **阶段与传输层时限不一致。** 实测长写作达到 60 秒时，连接层仍会断开；即使阶段放宽为 85 秒，也会先取消再重发，无法有效利用时间。E 写作阶段现临时同步两层时限为最多 85 秒，受整题剩余时间减 35 秒限制；结束或异常均恢复原设置，其他题型不受影响。
9. **复审缺少邻段引用证据。** 复审展示变更相邻段落时，现同时提供这些段落引用的原文；避免只提供改句证据却要求审查邻段。归因校验也合并所有已发现错误，一轮修订处理，不逐项消耗机会。
10. **把自审意见当作接口错误。** 官方要求直接交付合法 JSON 与完整报告，由平台判内容分；并不要求本地模型自审必须给 ok=true。前期候选版严格拦截语义意见，混合了真实内容问题、模型误判和修订失败，导致大量500。最终保留最近一次通过格式、引用编号/页码、已知方法归因检查的完整模型稿；经过有界修订后仍有意见或审查不可用，以 `audit.ok=false, mode=model_report_needs_review, delivered_attempt` 真实记录在内部证据中并交付该模型稿。不会给响应增加字段，也不伪造审查通过、评分或实验结果。所有内容质量仍由平台实际评判。这是交付策略调整，不代表解决了全部语义问题。
11. **生成异常的可观察性。** 一轮模型调用返回了证据 ID 但没有可读取的 markdown 字符串，随后重生成耗尽预算。现明确内部模型响应的字段、目标约2200字符，原始模型对象及修订对象写入内部 report_trace，以便区分漏字段、输出不完整及局部修订匹配失败；不会把未知字段猜作正式正文。

## 验证边界

本轮没有重新调用正式 D 会话，没有线上原始日志，也不据本地自拟题估算官方分数。最终真实 API 结果、回归计数和 tar 哈希见对应发布 manifest。
