# 正式论文库未知时的泛化策略

## 运行时材料边界

Agent 不把本地 300 篇论文当作正式知识库。正式运行先读取平台派题记录和当前案例的 `materials`，为该案例建立独立授权根目录；只对这些路径解析、切分和检索。论文数量、文件名、领域和 PDF 页数变化时，索引由内容哈希重新建立。

题目指定完整文件名时走精确文件名核验；未指定时才使用标题/摘要/章节/正文的混合召回。任何模型返回的文件名、chunk ID、页码、引用和图表路径都必须回到当前案例授权材料中验证。未授权文件不能因为“相关”而被加入答案。

## 新论文的自动适配

1. 读取 PDF、Markdown、JSON、TXT；PDF 按物理页保留标题、表格、图注和原文件名。
2. 对可提取页面做 600–900 中文字符或 300–450 token 层级切分，并保存文件哈希和片段哈希。
3. 扫描页单独标记；整篇不可提取才报告不可核验证据，单页无文字不会误杀整篇可读 PDF。
4. 索引采用文件名、标题/摘要、章节标题、正文和中英文术语变体的混合召回；C/E 再按论文逐篇补证。
5. 输出前验证引用、页码、正文长度、Markdown 文件同步和路径安全；失败时使用 `materials_missing`、`failed` 或缺证据错误，不猜测论文结论。

## 不依赖论文库规模的控制项

- 论文数量较少：不为了凑数返回低相关候选，B 类允许少于题目期望数量并记录原因。
- 论文数量较多：候选索引按当前题目授权范围构建，限制单题片段和模型 Token，避免把全库文件名塞入提示词。
- 领域未知：查询规划保留题目原词，补充中英文专名、方法、数据集和指标变体；不硬编码材料类别。
- 文档格式未知：通过签名检查和多后端解析选择路径；表格/图注单独留证，无法读取则不生成伪造数字。
- 多题连续执行：每题独立工作目录、索引和证据台账，不跨题复用结论。

## 300 篇库的用途

当前 300 篇 arXiv 论文库只用于本地压力测试检索、跨领域长文和未知文件名场景。它用于发现算法缺陷，不会复制进正式镜像，也不改变正式材料授权规则。正式平台换成任意论文集合后，代码路径和验证协议保持不变。
