核对 `科研助手赛题材料/research-agent-spec.md` 的 Survey、Reproduction 输入输出章节，以及 `赛题一组委会确认清单-逐项回复-20261015(3).md`、`research-experiments-20261020-source-v1` 的 README、D类实验要求、D类数据与图表判分规则、Agent适配与源码来源要求、离线自测与平台运行指南、报错对照与测试清单、三个 method/protocol、公开输入索引和平台客户端。

- C 返回只含 case_id/path/markdown；Markdown 保存到 `data/expert/<case_id>-综述-<RESEARCH_WORKSPACE_TEAM>.md`，与 JSON 的正文逐字一致。参考文献、页码和事实仍需来自授权论文。
- D 返回只含 case_id/status/metrics/figures；恰好三项精确名称和单位，未知数值为 null。图表在 `data/figure/<RESEARCH_WORKSPACE_TEAM>/`，由当前实际运行产生。缺少正式会话不能声称 completed。
- `<team>` 使用平台注入的工作目录标识，不使用报名队名或遥测 TEAM_ID。
- 正式 D 完整源码必须来自当前题 Gateway 回复，原样保存，再调用平台挂载的 run_experiment.py。没有在镜像放入预置完整算法，没有伪造正式凭证。
- 官方明确：失败可保留真实部分结果；后处理异常不得以占位失败答卷覆盖已经取得的真实结果。

## 代码修正

1. C 仍读取授权 PDF 全文、文本块及页码，关闭耗时的表格网格重建；为证据提取、语义核验、写作、修订和审查分配阶段截止时间，为落盘留余量。
2. C 模型给出不存在的片段编号时，只允许用本篇唯一匹配的连续真实摘录恢复。已知其他论文编号、歧义或无法找到原文时继续拒绝。此前行为是丢弃该证据，并未复现所谓空对象异常。
3. D 原来只识别 name=…/unit=…，现兼容明确的带引号字段、括号单位、Markdown 表格；与当前挂载 protocol 的题号和三项指标核对，按协议顺序提交。不按题号猜测或改名数值。
4. D 实验目录只解析为授权材料，不再对 protocol/sample/method 建立论文索引。
5. D 的 failed 若含实际部分观测，必须与本次运行 proof 完全一致才能通过本地校验。保留客户端的真实失败状态、已有数值与实际图表；不冒充 completed。没有证据的失败数值仍拒绝。
6. 客户端回执先存 `platform-submission.json`，日志先保存，再处理指标和图表。后处理失败保留原回执和异常，继续明确报错，不清空真实结果。无正式会话则正常落盘 materials_missing、三项 null 和 figures=[]。
