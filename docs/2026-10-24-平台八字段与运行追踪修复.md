# 八字段输入与 AgentRuntime 追踪修复

关联评测：`eval-20261024-d031f009`。平台 A-05 返回 HTTP 422，同时提示 `AGENT_RUNTIME_TRACE_MISSING`；该轮未完成、不计成绩。

## 根因与边界

`agenthack/base:1.1.1` 内的 `AgentRuntime` 路由参数为 `TaskRequest`，要求 `task_id` 和字典类型的 `input`。赛题一平台直接提交八字段题目，题目中的 `input` 是字符串、`constraints` 是字符串数组。请求在 FastAPI 参数验证时被拒绝，尚未进入 SDK 的 `telemetry.session()` 和 `task()`。因此该路径没有业务模型调用，也不会生成本题的运行追踪。

这解释了当前镜像可复现的 422 和无追踪路径，但不能凭本地检查断言平台收集器始终正常。修复后若仍缺追踪，需要携评测编号及实际运行日志继续核查平台链路。

## 修复

新增 `integrations/http_runtime.py` 的 `ResearchAgentRuntime`。它直接接收并校验题目，将任务转换为 SDK `TaskRequest` 后调用 SDK 原有路由，再将成功结果转换回题型 JSON。官方 SDK 源码和 OTLP 配置不变；没有另外生成替代追踪或绕过采集检查。

- 官方 session/task、真实工具装饰器和模型自动采集继续生效。
- 原始 HTTP 请求传入 SDK，保留 W3C `traceparent`；传入的任务和会话关联头按值传递，未提供任务标识时使用当前 `case_id`。
- 直接请求的超时取单题配置，最多 180 秒；不继承 SDK 的缺省 30 秒。
- 直接请求只返回当前题型对象；旧 SDK 包装请求仍兼容。
- 真正的业务失败返回非 200 状态，且 SDK 仍记录失败追踪；非法题目仍返回 422。

## 已完成的验证

真实 Linux SDK 回归 7 项通过，覆盖直接 A-05、原始题目保持不变、父追踪/任务/会话关联、75/180 秒时限、旧包装、异常、超时及非法输入。

在 1 CPU / 1 GiB、无外网容器内运行实际 `agent.py`，另启本地模拟模型网关与 OTLP/HTTP 接收器。A-05、B-01、D-01 材料缺失，以及 A-06 旧包装请求均返回 200 并核验落盘。OTLP 接收器实际收到 `agent.session`、`agent.task`、`agent.tool`，A/B 同时收到 `agent.llm`、`agent.http`；父追踪关联保留，调用与 Token 计数为模拟网关实际响应。

这属于协议与追踪工程验证，不是官方评分或 D 类正式来源凭证验收；未使用真实模型 Key。材料根目录仍需按平台实际挂载位置显式配置，不能将整个工作区设为论文库。
