# 平台 HTTP 422：生产入口与派题格式不一致

用户提供的真实平台截图显示 A-03、B-01、B-02 在约147–220ms内返回HTTP422，模型调用、Token和模型耗时均为0。平台明确提示 `/solve` 必须直接接收八字段题目JSON。此故障发生在请求验证阶段，与镜像上传大小或模型回答质量无关。截图未显示镜像不可变ID，不据此推断其具体标签。

已确认v6代码在生产中直接运行官方SDK1.1.1的AgentRuntime。SDK的TaskRequest要求task_id和字典类型input；直接题目的input是字符串，因此验证失败。开发服务器虽支持直接题目，生产容器并不走开发服务器。以前镜像验收统一发送SDK包装请求，遗漏了平台真正使用的请求格式。此前本地通过记录仍属包装格式的测试结果，不能代表直接派题或正式平台通过；撤回v6提交推荐。

v7仅适配HTTP边界：直接验证八字段题目，转换后调用原SDK路由，由SDK执行智能体并管理超时、取消、模型拦截、traceparent传播及遥测flush。成功结果解包为题目规定的JSON；执行失败返回HTTP错误，不能伪装成功。旧SDK包装请求仍保留原响应与计量metadata。健康检查沿用官方SDK。

新增生产SDK的真实ASGI HTTP回归，覆盖五类题、A-100、错误输入、题号一致性、会话和trace传播、旧SDK兼容与取消。镜像验收改为直接发送并保存wire-request.json，仍保留包装格式兼容/计量及故障检查。所有执行归入既有Harness的同一主对话，原始失败不覆盖。旧v6与新v7必须分开归档；新版本正式平台结果尚未取得。

执行结果、不可变ID及交付哈希由完成后的验收报告记录；本文件的设计说明不代表测试已经通过。


## v7实际验收后的D05问题与v8修复

v7实际镜像主轮127PASS/1FAIL/1官方BLOCKED，独立D轮21PASS；入口适配6项全部通过。D05失败子例是公开“拒绝后同服务器重试”：t=0接受A任务，t=2拒绝因切换开销而赶不上截止的B任务后，本应仍在t=2的同一服务器执行下一个A任务；错误程序跳到未来截止事件，把A也错误标为deadline。旧内部9探针只检查了输出守恒与已有轨迹合法性，漏掉该控制流。

v8新增截止拒绝、超窗拒绝和连续拒绝三探针，明确拒绝不能更新时间、上个流或已分配量；必须原时刻继续尝试同服务器。核对完成/丢弃状态和具体派发时间。原始v7错误源码SHA为758806f095d81dbc78b8f2818b1e7dc5b39f5224bf1723c367a32abe1a5c8a0a，冻结为测试数据，验证重复拦截与完整源码修复反馈。模型实现仍只能来自当题完整回复，不就地修改其算法。v8完整验收尚待执行。
