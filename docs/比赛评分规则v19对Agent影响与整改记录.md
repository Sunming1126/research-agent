# 比赛评分规则 v19 对当前科研助手 Agent 的影响

更新时间：2026-10-20

依据：`科研助手赛题材料/比赛评分与采集规则-competition-20261019-v19.md`。

## 结论

有影响，但不是接口重写。v19 明确说明赛题一的八字段输入、A/B/C/D/E JSON 结构和 Markdown 产物协议没有改变；因此 `/health`、`/solve`、派题解析、授权路径和五类处理器的总体架构可以继续使用。影响集中在评分口径、D 类实验协议和正式赛题数量的认知。

## 逐项对照

| 规则 | 当前状态 | 处理 |
|---|---|---|
| 赛题一正式题量 | v19 为 11 题，A/B/C/D/E=1/3/2/3/2；当前 25 题各 5 题是压力仿真形态 | 保留 25 题模拟器用于压力测试；正式运行以平台 dispatch 为准，不自行补题 |
| C 类评分 | v19 按事实 0/0.6/1 分档和独立引文质量计分，页码不影响分数 | 继续保存逐条 Claim Ledger、原文短摘录、文件名和页码；不把本地代理分数当正式榜分 |
| E 类评分 | v19 按八要点分档，并乘专属性系数；技术方案不足、无基线或无量化指标会扣分 | 已保留证据先行流程；后续重点提升基线/改进组、量化指标、失败边界和专属性 |
| C/E 引文匹配 | 允许排版归一、省略拼接和相似度匹配，最终回填真实切片，摘录最多 160 字符 | 当前实现保留原文核验和回读；不得用模型臆造摘录替代材料 |
| D-01/D-02/D-05 | v19 要求平台受控真实运行、私有产物和新冻结协议；旧 helper/旧数值不能当正式证据 | 平台模式继续只调用 `/data/experiments/run_experiment.py`；本地实验只作开发验证 |
| D 回执状态 | runner 版本可能返回 `complete` 或 `completed` | 执行器已将 `complete` 归一化为内部 `completed`，最终 Schema 仍只输出 `completed` |
| 求解时间 | v19 将输入解析、模型调用、检索、实验、校验和序列化全部计入；容器启动和健康检查不计入 | 保持单题串行、预算和超时控制；本地耗时不能宣称官方成绩 |
| Token | v19 只展示，不计入客观榜分；专家复核另行处理 | 继续记录 usage 到 receipt，绝不把 Token 自行合并进客观分 |

## 目前不需要改动的部分

- `/health` 和 `/solve` 接口及容器端口约定未被 v19 修改。
- A/B/C/D/E 顶层 JSON 字段未被 v19 修改。
- 材料授权根目录、路径越界检查、JSON/Markdown 回读和图表路径校验仍然适用。
- 300 篇论文库和 25 题仿真仍可用于泛化性、冷启动和资源压力测试，但不代表官方 11 题榜分。

## 仍需在正式平台联调时确认

1. 平台实际挂载的 v19 `run_experiment.py`、D-01 `implementation.py` 和 `layered-d-v3` 公布 ZIP。
2. 平台实际使用的模型网关、单题硬超时和资源上限。
3. v19 所述私有签名产物字段是否需要由平台 runner 自动补齐。
4. 正式派题的 `dispatch.json` 是否使用 v3 字段及其哈希校验字段。

## 代码变更

`src/research_agent/workflows/experiments.py` 已增加 runner 回执状态兼容：平台返回 `complete` 时先归一为 `completed`，随后仍执行三个指标、图表、路径、哈希和当前运行证据校验。没有真实平台 runner 时不会伪造 D 类完成结果。
