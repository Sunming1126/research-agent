# 科研助手 Agent：真实论文三轮本地评估

日期：2026-10-17  
模型：`deepseek-v4.1-flash`，经用户指定的 Ark 网关调用  
评分依据：赛事材料中的 `research-assistant-objective-v2`（见 [评分规则](../科研助手赛题材料/research-scoring-rules.md)）

## 结论摘要

三轮均使用真实 PDF 和当前 Agent 独立作答，每轮 A/B/C/D/E 各一题。**本地诊断分依次为 75.00、70.13、88.21/100**。第三轮五类题全部产生合法结果；检索在三轮中均找回全部目标 PDF 且没有多余文件。最主要的问题是 C 类综述：前两轮因证据审查失败而整题得 0 分；第三轮可提交，但仅覆盖冻结事实的 4/10，C 类得 16/25。

这不是正式榜分。正式一轮是每类五题、共 25 题，再取五题类别平均；本报告每类只有一题，题目和人工金标准均由本地自建。平台私有金标准、可信 syscall 记录、专家与 Token 复核分不可见，最终综合成绩保持 `null`。公开 D 类小实验也不等于复现下列论文的原始 benchmark。

## 本地评分办法

评分程序见 [scoring.py](../evaluation/scoring.py) 和 [score_runs.py](../evaluation/score_runs.py)。失败与非法输出为 0 分；未终止题阻止汇总。`official_shape` 模式强制每类五题，`diagnostic` 模式强制每类一题，不允许混算。

| 项目 | 诊断口径 | 满分 |
| --- | --- | ---: |
| A | 非空回答 3，非空澄清问题 2，先过 Schema | 5 |
| B | 完整文件名大小写不敏感去重；`clamp(15H/N−0.75U, 0, 15)` | 15 |
| C 事实 | 预先冻结 10 项，人工核对正确覆盖数与严重错误；`clamp(15C/10−3F, 0, 15)` | 15 |
| C 引文 | 五篇指定论文须同时有正文引用和参考文献条目，每篇 2 分 | 10 |
| D 流水线 | 本机可见的八项运行证据，每项 2.5 分 | 20 |
| D 数据与图表 | 三项实测指标按公开容差公式各 4 分；PNG 与六项图表要素按比例计 8 分 | 20 |
| E | 动机、路线、实验、命名基准、量化指标、可行性各 1.5；复现瓶颈、多文献互补各 3 | 15 |

C/E 的逐项人工判断和证据位置保存在 `evaluation/judgments/round-N.json`。C 引文覆盖、B 文件名、D 产物和指标由程序重读。D 指标参考值取自组委会公开 `research-experiments/references.json`，时间/吞吐指标在 Windows 主机与公开标定环境之间不可直接解释为算法退化；仍按公开公式计算诊断分，以暴露这种偏差。

原始结果、运行收据、证据台账、D 图表与逐项分数分别保存在 `output/evaluation/round-1/`、`round-2/`、`round-3/`。例如第三轮 [综述 JSON](../output/evaluation/round-3/data/eval_r3/C-03.json)、[综述 Markdown](../output/evaluation/round-3/data/expert/C-03-综述-eval_r3.md)、[评分明细](../output/evaluation/round-3/local-score.json)。C/E 的 JSON 与 Markdown 已由 Agent 回读比对。

### 第一轮：75.00 分

- **做得好：** B 返回 RAG、FiD、Self-RAG 三篇目标论文，无多余项，15/15。D-01 真实生成指标、CSV、PNG 和运行日志，三项指标均在公开容差内，40/40。E 的动机、技术路线、基线、实验、指标、复现瓶颈、互补机制和可行性都有可定位段落，15/15。
- **失分原因：** C 起初因模型改写原文摘录而无法逐字定位；丢弃无效摘录后，后续草稿又加入证据台账未支持的实验细节，审查拒绝提交，按 0/25 计。
- **轮后调整：** 无法核验的摘录直接丢弃并留诊断记录；收紧报告提示，要求页码与事实台账严格对应，并允许两次带反馈的修复。

### 第二轮：70.13 分

- **做得好：** B 准确返回 DPR、BEIR、RETRO，15/15；A 5/5。D-02 的 Recall@5 和 MRR@10 都与公开参考值一致，流水线和图表检查全过。
- **失分原因：** C 在多次草稿中仍把不同页、不同 claim 的细节压进同一事实句；审查认定部分归因超出逐条证据，最终没有合法综述，0/25。E 提到了 PopQA 等现有论文数据，但没有明确选定本 Idea 将使用的命名医学基准，人工扣 1.5 分。D-02 查询吞吐实测约 `10557.80 queries/s`，公开参考约 `3185.11 queries/s`，超出容差后该项只得 0.63/4，D 合计 36.63/40；这是跨环境速度差异带来的诊断扣分。
- **轮后调整：** 增加只从已核验事实台账逐条组装的 C 类保底综述，使自由长文审查失败时仍能提交可追溯结果；Idea 提示明确要求选定命名基准与适配方案。

### 第三轮：88.21 分

- **做得好：** B 准确返回 RAG、Self-RAG，15/15；E 明确选择 NaturalQuestions、TriviaQA，并给出置信度触发、证据筛选、FiD 式融合、消融、量化指标、瓶颈与失败边界，15/15。C 的模型长文这次通过审查并引用全部五篇论文，保底模板没有触发。
- **仍需改进：** C 的五篇引文覆盖得 10/10，但十项冻结事实只完整覆盖 4 项，事实分 6/15，合计 16/25。主要漏项是 DPR 双编码器与 BM25 top-k 比较、RAG 参数/非参数记忆及 RAG-Sequence/RAG-Token、FiD 段落数对照、RETRO 两万亿 token 检索库与参数效率。没有判出严重事实错误。D-03 流水线与图表全过，缓存命中率与 P95 延迟在公开容差内；推理吞吐实测约 `5479.70 samples/s`，参考约 `1679.71 samples/s`，该项得 1.21/4，总分 37.21/40。
- **轮后判断：** 证据安全性已有改善，下一步应按题目要求建立“每篇论文必答事实清单”，在生成前检查关键方法、数据、指标与结论覆盖，缺项时定向补检索或补写，而不是仅增加文章长度。

## 验证与实际边界

- 本地评分与摘录保底逻辑的 6 个单元测试通过；项目回归共运行 26 项，24 项通过，2 项因 Windows 文件系统大小写行为和符号链接权限而跳过。公开实验挂载已启用，含 25 题模拟派题的回归通过。
- 第三轮五个结果均写入并回读，C/E 另存 Markdown 与 JSON 正文一致；D 保留真实 `metrics.json`、`source_data.csv`、`command.json`、stdout 事件、PNG 及哈希。
- 三轮合计 15 题中 13 题完成、2 题 C 类失败；已再次逐项核对全部 13 个完成题的收据产物哈希，全部匹配。
- B 查询明确包含论文方法名，七篇候选库较小；三轮 15/15 不能外推到正式大论文库。C 人工事实清单也是本地设计，平台冻结答案可能不同。
- 本轮为 Windows 本机评测，未重新完成 Linux Docker 镜像构建和正式平台 25 题联调。D 时间与吞吐的参考环境不同；本报告只呈现公开实验代理分，不推测平台私有 D 分。

## 下一步优先级

1. **C 类事实覆盖：** 在每篇论文召回后建立题目维度清单，对缺失的核心事实定向检索，再生成报告；优先补 RAG 两种形式及跨论文对照。
2. **D 类环境一致性：** 在正式容器资源配额下复跑 D-01 至 D-05；计时类指标只根据该环境的真实运行记录判断。
3. **正式提交前：** 使用平台实际派题记录测试全部 25 题，确认 Docker `/health`、`/solve`、文件路径、超时与预检查；最终版本、API 配额和上传规则由人工按官方公告确认。

本报告的每轮分数可由 `python -m evaluation.score_runs --round N` 重算。评分器、冻结题目、人工判断和原始输出分开存放，便于复查和改动权重后的再计算。
