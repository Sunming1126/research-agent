## 源码观察

- PaperQA2 的 `src/paperqa/agents/tools.py` 将论文搜索与 `gather_evidence(question)` 分为两个工具，后者可用更窄的问题重新收集证据。这提示本 Agent 的 C/E 类可以按“方法、数据、指标、局限”分别检查证据覆盖，不应只用一次宽泛查询。
- STORM 的 `knowledge_storm/storm_wiki/modules/article_generation.py` 按一级章节分配资料再生成段落。这提示 C/E 长文在写作前明确比较维度和每篇的证据角色，有助于避免某篇事实集中、另一篇缺证据。
- 两个项目都可以接外部搜索或嵌入服务，但赛事授权材料和离线约束更严格。本项目只能使用题目指定论文；不会把这些项目的网络抓取、自动扩展论文库或第三方云向量库移入正式 Agent。

## 本项目适用的优化

1. B 类继续保留原题、改写和独立子问题多通道召回；对逐个子问题的候选分数和误报做日志检查。
2. C/E 写作前生成固定比较维度的证据覆盖表。缺口仅从当前题授权论文补检，不根据外网补事实。
3. 长文引用仍以本项目的原文摘录、文件名与页码校验为准；参考项目的生成内容不能视为证据。
4. 在 300 篇压力测试中重点检查冷启动耗时、内存、Token、B 类漏召和 C/E 跨论文归因。

上述优化先作为待检验假设；每两轮根据实测记录决定是否改动，不为单个冻结题硬编码答案。
