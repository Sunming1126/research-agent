# 官方 11 题全 error 的逐项诊断

核对对象：最新已交付 `research-assistant:0.4.3-runtime-20261024`；用户提供的本轮报告完成时间为 2026-10-24 14:47。该报告未包含本轮评测编号。11 题均标为 error，不是 11 份合格答卷经内容评分后恰好得到零分。运行证据完整性已验收与题型答卷有效性是两个检查。

本次重读了用户整理后的科研助手赛题材料；当前 research-agent-spec.md 与官网公开版本一致。目录整理造成的历史文件删除保留原样，没有恢复旧文件或改变用户整理结果。

## 1. 已确认：0.4.3 的最终 HTTP 响应没有满足题型顶层 Schema

科研助手格式规范要求输出仅包含当前题型字段。Chat 的顶层字段为 case_id、answer、clarifying_question；D 为 case_id、status、metrics、figures。

0.4.3 保留了官方 SDK 整个响应，顶层实际为 task_id、status、output、metadata；正确题型对象位于 output.answer 的 JSON 字符串内。客户端若按公开规范直接校验 HTTP JSON，就会因为没有顶层 case_id 等字段失败。

在已交付镜像内，用真实 SDK、输入中间件与可控的合法 Chat 输出复现：

- HTTP 返回 200，SDK metadata 有真实 trace_id；
- 解开 output.answer 后，题型对象通过现有严格 Schema；
- 同一校验直接用于最终 HTTP 响应，报 case_id mismatch。

原始记录：`output/official-zero-score-20261024/wire-schema-reproduction.json`。测试没有调用真实模型。它确认了输出边界契约错误；平台是否还叠加结果路径问题，不能由此排除。

这是上一版为保留 SDK metadata 而引入的实现错误。此前 55 项通过验证了运行时、内部答案、文件与 OTLP，却没有把最终线上形态的响应当作题型答卷再做严格校验，验收范围不足。不能继续把 SDK 执行成功当作平台答卷有效。

纠正时应保留原生 AgentRuntime、官方路由、真实任务/工具/模型采集和 OTLP 导出，同时让直接题目请求的响应满足赛题 Schema。追踪元数据不应混入题型顶层字段。修改后须在同一次测试中检查最终响应、文件及 OTLP，不能只分别验证其中一层。

## 2. B/C/E：存在独立的模型前材料适配问题，但线上具体路径未公开

本轮 A 调用模型一次、625 Token；全部 B/C/E 为零模型调用，约 0.15–0.36 秒结束。不能归因为检索排序或长文质量下降，优先检查材料解析及索引初始化。

当前实现仅默认授权专用 `/data/论文库`，并为公开 B 描述 `本地论文文件夹内的 PDF` 提供一条默认别名；其他描述须明确配置。可复现的限制包括：

- 即便绝对路径指向允许论文库内的文件，当前解析器仍统一拒绝绝对路径；
- 规范中的 C 示例材料描述 `本地论文文件夹内指定的电池回收 PDF` 无法直接定位，它是描述，不是实际文件名；不能因此自动读整个论文库；
- 如果实际只读论文库位于另一工作区布局，而平台没有显式配置 RESEARCH_MATERIAL_ROOTS，当前默认路径不会自动匹配。

场景复现：`output/official-zero-score-20261024/material-contract-scenarios.json`。这些是局部代码限制，不是已经取得了本轮实际 materials、挂载参数或异常类型的证据。

用户报告归档数为 16、19、22、25、28、31、36、41、46、49、52。B/C/E 每次增加 3，恰与引擎异常路径写出的 diagnostic-evidence.json、error.json、session.json 数量一致；D 每次增加 5，也与材料缺失答卷路径吻合。这支持检查这些分支，但文件计数不能替代原始异常记录。

公开派题说明只规定相对工作区路径，并明确 HTTP 实际挂载位置由平台协议决定，没有给出可直接确认本轮挂载的参数。需平台确认当前题材料描述的解析方式、授权材料实际根目录及本队工作区标识；不需要提供密钥或原始答案。

## 3. D：模型零调用意味着本轮没有完成当前题源码生成

新版 D 要求当前题 Gateway 生成源码、原样保存、申请来源凭证、执行正式客户端。三道 D 都为零调用，不能把它们当成已跑算法后被评零分。

引擎在进入 LayeredDRunner 前先用统一 DocumentIndex 解析 case.materials；默认根只有论文库。如果材料列表包含当前题实验目录/脚本，且没有对应的授权目录适配，会提前产生 MaterialError，并进入 materials_missing 路径，而不是源码生成流程。当前题实验目录由平台按 `/data/experiments/<case_id>/` 挂载，应按真实当前题授权接入，不能扩大到所有实验题，也不能用本地公开包代替正式会话。

D 指南本身说明“返回结果或保存文件不符合规范”为通用提示，不足以确定是字段错误还是来源准入问题。现阶段更应先检查能否读到当前题材料、返回的最终题型对象与 SDK 外层对象，再查正式执行。

## 4. 新增正文限制与 Idea 保底流程冲突

最新规范新增 c1-output-limits-v1：

- Survey 正文最多 4500 字符（包括空格、标点和 Markdown 符号；参考文献前），引用实例最多 40 个；复合引用分别计数。
- Idea 正文最多 6000 字符，建议 1800–3200；禁止程序动态拼接、硬编码扩写或无关通用段落。

当前 validation.py 没有最大长度或引用次数上限。reports.py 仍会在 Idea 修订失败后调用 deterministic_idea() 拼接固定通用方案，不能按新规范当作有效保底。这些均需调整。

本轮 C/E 没有调用模型，不能用正文过长解释它们当前的失败；这是接下来必须补齐的兼容缺口。
