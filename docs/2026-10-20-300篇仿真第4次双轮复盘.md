## 本轮问题

- 第 7 轮 C-02 的模型把原论文正文内部参考文献 `[14]` 原样带入本题 Markdown，触发本题引用校验；这和前面发现的晶向 `[111]` 属于同一类“学科方括号记号”。
- 第 8 轮 B-03 的目标论文进入了高分候选，但一次模型审批写错了片段 ID。安全校验正确拒绝了无证据批准，却没有给该高位候选一次修复机会。
- 第 8 轮 E-03 遇到 `APIConnectionError`，说明正式评测中网关短时断连会把本来可完成的题直接记为失败。
- C/E 长文耗时范围约 35–105 秒，仍低于本地 300 秒单题预算；D 类五个公开实验均保留真实指标、图表和运行证据。

## 本轮实施的优化

1. 事实台账把原论文内部 `[数字]` 转为“文内所引”，不改变事实含义，也不让它冒充本题参考文献；合同校验继续只识别一、两位本题引用编号。
2. 对分数至少 0.5 的候选，若模型首次只写错片段 ID，最多追加一次单篇重审；重审仍须使用当前候选真实 chunk ID，不能凭文件名补证。
3. 模型网关对连接错误、超时、限流和 5xx 做有限指数退避；模型返回非法 JSON 时同样最多重试两次，所有真实请求仍计入单题预算。
4. 将 `openai==1.109.1` 及其传递依赖按 Python 3.12 重新下载到 `local-workspace/python-deps`，并同步固定到 requirements.txt 和 Docker 构建记录。
