## 本地复现与修复

在原 0.4.8 镜像及原生 AgentRuntime 中，8 个 B 检查有 7 个失败，均可形成 HTTP 500：坏 PDF、目录中的损坏 JSON、非 UTF-8 文本、同名副本、材料缺失、带目录的 PDF 通配范围、明确整库描述的另一种写法。记录：`output/b-failure-matrix-049/before.xml`。这些是可复现的软件缺陷，尚不能称为本轮线上根因。

本次修改：

1. B 候选库只纳入 PDF，不把目录中的 JSON/文本辅助文件当作论文解析。单篇解析失败保留诊断，其余可读论文继续正常检索。
2. 相同文件名、相同内容的副本去重；同名而内容冲突的文件不猜选，记录冲突。指定单文件有歧义、未知主题范围和越界路径仍拒绝，不扩大授权范围。
3. 支持明确的整库描述和限定 PDF 通配范围；指定目录始终经过授权边界检查。
4. 损坏的 B 索引缓存从原始授权 PDF 重建；深入正文阶段同样隔离解析故障。其他题型的严格缓存校验保持原状。
5. B 无法完成时保存 `{"case_id":"本题编号","papers":[]}`；错误原因放工作目录及响应头，保留原生 SDK 的失败状态，不伪装成正常检索无匹配。不能写文件或派题身份/哈希未通过时仍报错，不宣称已保存。
6. 正常结果继续执行文件真实性、字段、去重与读回校验。诊断增加材料解析详情，便于组委会按归档查具体失败。
7. B 不重建表格网格，仍读取表格文本块和页码。候选库小于 50 篇先读前 8 页，50–249 篇前 4 页，250 篇以上前 2 页，再按检索候选与剩余预算补读全文。大库初筛不是全库全文精读，存在深页信息初筛漏召回风险。

空数组的失败答卷不能代替真实检索，也不保证通过平台内容判分或证据验收。本地实测成功案例必须返回非空真实论文，不能靠空数组通过本次验收。
