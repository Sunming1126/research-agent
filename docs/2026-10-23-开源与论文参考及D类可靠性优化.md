## 具体改变

1. D-05 公开自测从一个原始输入扩展为六个输入：原始样例、空任务、空闲后换流、首次任务晚到、并发任务、截止时间/切换/窗口组合。探针只使用当前题公开的协议与流标识，不读取隐藏数据，不携带参考算法或正式答案。
2. 自测共用最多八秒的时间额度，D-05 每个探针最多两秒，并始终为后续阶段预留时间。超时会终止子进程，把对应公开请求提供给修复模型。
3. D-05 进一步检查派发顺序、丢弃原因与排序、跨空闲间隔的流切换开销及已完成任务守恒。宽松窗口的简单探针还会检查任务全部完成，防止以全部丢弃绕过验证。它们不是正式调度等价性证明。
4. 修复反馈带上一版源码与失败输入；每轮 `source-attempt-N.json` 和 `implementation-attempt-N.py` 分别保存，最终 `implementation.py` 仍只经过允许的换行规范化。
5. D-01 在同一公开输入、固定 seed 下重复运行，比较预测和实际模型参数。仅将 `details.elapsed_seconds` 作为易变诊断单独记录，避免把时钟变化误报为预测漂移。提示词要求不将真实耗时放入算法数据。
6. layered D 正式客户端使用可取消的子进程轮询，时间上限取整题剩余额度。超时保留已得到的 stdout/stderr；平台 `D_SOURCE_*` 错误码写入独立诊断，不额外添加最终提交字段，也不把平台审计故障归因成算法不合规。
7. 真实模型验收发现 E 类保底报告将多行原文数字与页码拆开，触发引用失败。渲染时折叠 PDF 排版换行，并为已绑定证据的每个事实句补齐同一物理页码；证据台账原文保持不变，未引用数字仍会被拒绝。

## 构建与证据

默认构建仍使用 `agenthack/base:1.1.1`。此次直接从官方基础镜像构建时，PyPI 的一个依赖下载超时；实际产物复用已验收的 0.3.0 镜像作为依赖基础，在禁网条件下再次按相同的 requirements 校验并复制最新版源码：

```powershell
docker build --network none --platform linux/amd64 --build-arg BASE_IMAGE=research-assistant:0.3.0-source-v1 -t research-assistant:0.4.1-source-v1 .
```

旧镜像、官方基础镜像和新镜像需明确区分。镜像身份、源码哈希、实际测试结果和导出文件校验值见交付目录的构建清单与验收报告。

全项目第一次回归在 0.3.0 的相同依赖环境中挂载新源码执行，禁网、1 CPU、1024 MiB，得到 124 passed / 4 skipped。卡死注入和两版源码回放使用明确标注的离线夹具；它们证明编排行为，不冒充真实模型质量。真实模型验收单独使用已构建的 0.4.1 镜像，记录保存在工作区 `镜像测试/runs/optimization-20261023-v041/`。

挂载公开实验后为 127 passed / 1 skipped；加入多行引文回归后的最终全项目结果为 **129 passed / 1 skipped**，唯一跳过项是本机未安装的 300 篇论文库场景。真实模型关闭思考的独立轮次 `optimization-20261023-v041-verified` 已通过 D01/D02/D05 共 **13/13** 个 Python3.9公开输入，E类首次失败及修复后复测分别保留。High 思考的初轮出现回复截断，不能声称该配置通过；当前推荐的本地 Harness 验收配置为显式关闭思考。这是配置范围，不能推导成官方成绩。

最终镜像的 C/E 定向复测均通过；两类各 25 条证据、共 50 条摘录均在对应 PDF 物理页找到。D01/D02/D05 在第二个独立 Python3.9 容器重放结果相同。正常 D05 真实测试第一版被空闲间隔探针拒绝，第二次完整模型生成通过六项内部探针及七个外部公开输入。

额外历史故障回放中，新自测识别了旧版卡死，但一次真实修复生成使用私有运行时属性，被子进程静态检查拒绝，按两次上限停止。这条记录保留在 `optimization-20261023-repair`，不能写成修复成功；模型修复仍有失败概率。证据页码存在也不等于所有语义或原创性已通过人工审查。

正式平台来源签名、私有输入、可信最终指标及官方得分仍需平台会话，不能用本地 Harness 签发或替代。当前自测子进程使用镜像 Python 3.11，兼容性另以 Python 3.9 容器执行公开输入验证。
