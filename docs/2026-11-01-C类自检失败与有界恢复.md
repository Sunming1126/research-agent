# 2.0.1-c1：C 类自检失败恢复

## 证据与结论
用户报告 2.0.0 官方 C-01 HTTP 500、2 次模型调用、约 66 秒，后台反馈为 Agent 自检证据/引用/输出格式后主动抛错；C-03 正常。2.0.0 与 B6 是同一镜像内容。
源码与反馈相符：`compose_report` 没有通过本地检查的完整稿时最终抛 EvidenceError，HTTP 层按真实失败返回 500。C 旧流程仅两轮；第一次写作不合格，第二次修订定位/格式失败就停止。后台反馈不能确定究竟哪个引用、字段或段落触发了异常；没有本次原始答卷与异常堆栈，不声称锁定唯一线上根因。

## 已定位并修复的机制
- 内部 `used_evidence_ids` 类型错误可使完整正文作废。C 现在仅从正文的显式证据标记、合法论文编号和实际页码回查授权台账；内部列表不是官方输出字段。
- 严格精确文本补丁容易因模型复述原段落失败。C 增加段落编号寻址、编辑范围检查、原子应用及再次验证；拒绝不存在、重叠或重复目标。
- 首稿/格式修订最多三轮，修订失败可在剩余时间充足时再生成完整模型稿。写作首轮最多90秒并预留55秒，重新生成最多55秒并保留10秒；修订仍受原有单题deadline、token预算控制，无限重试被禁止。
- 显式证据标记中的全半角、空格、大小写、分隔符差异可在ID完全已知时规范化。不能猜测未知ID、页码、引用范围，也不能把未闭合标记当普通文本漏过。
- 语义审查返回错误类型、超时或修订失败不能丢失已通过硬检查的完整稿；审查疑虑真实保留为 `model_report_needs_review`，绝不写成审查通过。
- 持续未知引用、虚构页码、少于五篇实际引用、短于800字符、超过4500字符或40引用等仍不可交付；额度拒绝、无完整稿仍真实失败，不伪造成功或用模板凑正文。

## 修改边界
在桌面仓库 `test1-2` 的 C 专用处理路径实现。新增 `survey_repair.py`；修改 `survey_prompt.py`，公共 `prompts.py` 仅增加 Survey+段落编号修订提示路由；公共 `reports.py` 的恢复、引用和时限处理受 `Survey` 与原文写作模式条件控制。没有恢复 B7。
镜像以固定 `research-assistant:2.0.0` 为基础，仅覆盖三个原有文件并新增一个 C 文件。其余55个运行文件、所有基础层与容器配置一致，包含 B/D/E 专用逻辑和原生SDK适配文件。哈希证明见 image-proof.json。
旧 B/E 阶段的冻结测试将 C 也冻结；本次根据明确的 C 修改范围更新这些检查，保留旧哈希清单，并增加非 C 提示、共享报告其他方法和 E 分派一致性检查。
