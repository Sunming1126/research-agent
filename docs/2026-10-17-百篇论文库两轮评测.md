# 百篇论文库与两轮科研助手诊断评测

> 本文保留两轮原始运行及当时的修复状态。后续第 5 轮已完成独立复测，得 94.00/100；E 类还进行了定向优化。最新结论见 [百篇论文库复测与智能体优化复盘](2026-10-17-百篇论文库复测与优化复盘.md)。下文“尚未复跑”仅描述原始两轮报告形成时的状态。

日期：2026-10-17。评分为本地五题诊断分，**不是赛事正式榜分**；每轮 A/B/C/D/E 各一题，而赛事正式评测为每类五题、共 25 题。原始运行结果及评分文件保存在 `output/library-evaluation/round-4/`、`output/library-evaluation/round-5/`。

## 一、基于前三轮的优化判断

此前三轮真实论文诊断分为 75.00、70.13、88.21，详见《科研助手三轮真实论文评估》。B 类在七篇小库中三轮均为 15/15，但此前没有测过百篇干扰库；C 类第三轮仅覆盖 10 条冻结事实中的 4 条。复核发现两类根因：同篇长论文的许多片段会占满全局候选；综述抽取可能选中相关工作或评测表，却漏掉本篇方法与首页摘要。实验 D 类在本机有真实证据，但耗时指标与运行环境有关。

本次在第一轮前完成了论文级候选去重、首页与跨页证据选取、每篇 3–5 条事实抽取提示，以及大库专用测试。第一轮后进一步修复 PDF 断词/连字造成的真实短引文误拒，并在 C 类正文中列出可回查的逐篇事实。第二轮暴露的新问题已在代码中修复，但修复后的真实模型结果**尚未复跑**。

## 二、本地模拟论文库

- 共 **100 篇互不重复的真实 arXiv PDF**：前期已核验的 7 篇，加新下载的 93 篇。源页面、PDF 地址、标题、摘要、学科、物理页数、文件大小、SHA-256 均在 `paper_library/manifest.json`。
- 逐文件回读：100 个 PDF、100 个唯一 arXiv 编号、100 个唯一文件名，PDF 文件头和 SHA-256 全部通过；合计 **266,746,099 字节**、**2,311 页**，页数范围 5–70。
- 十个领域方向：信息检索 12、自然语言 15、计算机视觉 10、统计机器学习 9、数学优化 9、定量生物 9、星系天文 9、材料物理 9、经济学 9、光学 9。前七篇按本地测试主题归入 IR/CL，类别合计不代表 arXiv 的原生领域分布。
- 建成索引约 **53,077 个页级片段**，参考文献片段不参与事实检索。首轮建库在第 81 篇因 PDF 异常 Unicode 中断；修复后利用前 80 篇缓存续建，剩余索引用时 42.18 秒。**完整冷启动总耗时未测得**。第二轮复制并按内容哈希复核缓存，用时 1.11 秒。
- PDF 仅供本地研究评估，`paper_library/pdfs/` 已排除 Git 与 Docker；对外引用使用 arXiv 原始页面，不直接再分发原文 PDF。来源依据：[arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)、[API 使用条款](https://info.arxiv.org/help/api/tou.html)、[学科分类](https://arxiv.org/category_taxonomy)。

核验命令：`python scripts/verify_paper_library.py`。生成脚本 `scripts/build_paper_library.py` 可按清单断点续跑，并检查 PDF 签名、可提取文本、页数、文件大小与哈希。

## 三、两轮原始成绩

计分沿用公开 `research-assistant-objective-v2` 结构。A 验证两个回答字段；B 对冻结目标文件名计算命中与误报；C 对 10 条预先冻结的论文事实人工复核，并独立计五篇引用与严重归因错误；D 核对真实运行、三个指标、图表和工作证据；E 按八个研究方案要点人工复核。失败题计零，未将事后修复当作原始成绩。详细证据：`evaluation/library_benchmark.py`、`evaluation/judgments/library-round-4.json`、`output/library-evaluation/round-4/local-score.json`、`output/library-evaluation/round-5/local-score.json`。

### 第 4 轮

- B 在 100 篇中准确返回 RAG、FiD、Self-RAG 原论文，无多余文件；用时 16.33 秒。
- C 引用了指定的五篇论文，引用覆盖 10/10 分；10 条冻结事实中确认 6 条，同时把原始 RAG 的文档边缘化机制误概括为“查询前拼接”，严重归因错误扣 3 分，事实部分得 6/15，合计 16/25。未覆盖 RAG 两种形式、FiD 逐段编码与段落数实验、RETRO 的两万亿 token 检索库。初次短摘录校验还误拒了 RAG/FiD 的真实原文，因为 PDF 中断词和 `ﬁ` 连字与模型摘录排版不同。
- E 涵盖动机、路线、实验、具体基准、指标、复现瓶颈、多文献互补和可证伪性八项；人工冻结要点为 15/15。
- D-04 真实完成，八个流水线检查点、六个图表检查全通过。三个指标中前两项满分，搜索耗时受本机计时影响，指标部分为 10.96/12，总分 38.96/40。

### 第 5 轮

- B 中文题目针对英文生物论文，查询改写后没有候选进入模型核查，结果空列表；三篇目标均漏召，得 0/15。
- C 在五篇指定生物论文中只抽到四篇的有效事实，未满足至少五篇证据的门槛，以 `EvidenceError` 失败，得 0/25。第五篇 PDF 首页有短标题、摘要尾段和完整摘要；选片策略偏向前两块，漏掉主体摘要。
- E 已从五篇论文抽取事实，也生成过草稿，但审查及多次修复耗尽单题 40,000 Token 预算，以 `ModelError` 失败，得 0/15。审查反馈中包含把可接受句子列为问题的情况；不能据此把草稿直接当成通过结果。
- D-05 真实完成，三个指标、八个流水线检查点和六个图表检查全部通过，得 40/40。

## 四、第二轮失败后的代码修复（尚未获得真实模型复测分）

1. **中英文召回**：查询提示明确要求生成英文专业术语；本地词汇扩展加入生物建模术语；若模型改写导致无候选，使用题目原词和排除条件再次召回。对第 5 轮原始中文题进行离线重算，三篇冻结目标现排在全库论文级候选前 3 位。尚需模型筛选环节再跑，不能写成 B 类已得分。
2. **摘要选取与 C 类兜底**：首页只优先选取足够长的实质段落，排除短标题、作者名单和孤立的 “Abstract” 标签；指定论文首轮零事实时，只回到该篇前几页补抽。C 类把已通过原文短摘录核验的事实逐篇列入正文，避免长文丢失证据。
3. **原文摘录核验**：校验允许 PDF 换行、连字符和连字字形差异，但仍要求连续的规范化原文字符序列；旧评测中 RAG、FiD、DPR 的多条被误拒摘录现在可通过，而包含跳接省略号的非连续摘录仍被拒绝。
4. **异常字形**：PDF 文本层中的孤立 Unicode 代理码位在解析入口替换为可编码字符，防止整库索引在计算哈希时崩溃。已对触发问题的第 81 篇 PDF 验证成功切片。
5. **模型预算**：C/E 报告修复尝试上限缩减；预算或审查失败时使用已核验 Claim Ledger 生成保守的本地保底文本。E 类保底包含研究问题、基线、实验、指标、失败边界与参考文献，明确标注新方案为待验证。它只能保证合法且有证据，不保证专家质量满分。

## 五、验证状态与下一步风险

- 两轮原始结果已经落盘，分数可用 `python -m evaluation.score_library_rounds --round 4`、`--round 5` 重算；第 5 轮失败题按零分保存，不用修复后代码篡改历史。
- 百篇库逐文件回读通过；本轮新增的检索、PDF Unicode、摘录核验、证据补抽、Claim Ledger 和 Idea 保底单元测试通过。之前完整项目回归为 28 项中 26 通过、2 项 Windows 限制跳过；本次最后一组改动后，当前沙箱不能读取本地忽略的 PyMuPDF 依赖，因此只完成了不依赖该目录的专项及评分测试，**完整回归仍需补跑**。
- 再次运行真实模型题时，自动审批因账户使用额度上限而拒绝，所请求的动作是联网调用模型诊断查询。拒绝原因是审批无法完成，**不是认定代码或行为不安全**。遵照审批结果，修复后的第 5 轮 B/C/E 未再联网复跑，也没有推断一个新的分数。
- 正式风险仍包括：100 篇约 5.3 万片段在赛事 1 CPU/1GB 容器中的峰值内存与冷启动耗时尚未验证；新近 arXiv 预印本不能代表经过同行评议；公开 D 小实验与正式私有实验、模型网关及榜单评分不能互相替代。待模型额度与测试环境恢复后，优先重跑第 5 轮 B/C/E、完整项目回归及容器资源测试，再决定是否调整提示词和检索阈值。
- 温缓存下的本机 Python 内存跟踪显示，载入 53,077 个片段并建立检索计数结构时，受跟踪的 Python 分配峰值约 90.5 MiB；该数字不包含解释器和原生库的全部内存，不能据此宣称 1GB 容器限制已通过。
