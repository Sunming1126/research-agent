### 1. 官方运行时正常启动，但没有赛题 HTTP 适配

启动链为 Dockerfile 第 15 行 `CMD ["python", "agent.py"]` → agent.py 第 71–73 行 → `AgentRuntime(ResearchAgent()).run()`。

因此，不能仅因源码存在 `ThreadingHTTPServer` 就判断正常镜像违反群公告。SDK 存在时实际执行的是官方 Runtime。SDK 缺失时，第 74–76 行会静默退到自建服务；正式入口应缺失即失败，把开发服务器放在显式的本地入口，避免无 SDK 时仍对外提供貌似正常的健康服务。

这个提交没有替换或适配官方 `/solve` 路由。参考 SDK 1.1.1 的 `runtime.py:27` 要求 `task_id`、字典 `input` 和对象 `constraints`；平台发送的是八字段题目，`input` 为字符串、`constraints` 为数组，且没有正文 task_id。因此会在调用 `ResearchAgent.solve` 前被默认模型校验拦截。这是源码推导，**不是本轮新跑出来的 422 记录**。

修改方向：保留官方 Runtime 作为服务所有者，在其应用入口完成八字段到内部 SDK 请求的转换，同时保留 Runtime 的超时、取消、任务上下文、模型统计和遥测。传输 UUID 从 `X-Research-Task-ID` / `Idempotency-Key` 获取，不能用 case_id 冒充；也不能靠另起自建 HTTP 服务替代官方 Runtime。

证据：[Dockerfile 第 15 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/Dockerfile#L15)、[agent.py 第 71 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/agent.py#L71)。

### 2. 磁盘结果正确不等于 HTTP 响应正确

agent.py 第 25 行将题型结果放入 `{"answer": json.dumps(result)}`，参考 SDK `runtime.py:64` 和 `:96` 又以 TaskResponse 对外返回。即使通过内部包装使请求进入处理流程，线上响应仍为 task_id/status/output/metadata，题型结果藏在 output.answer 字符串内。现有生产入口没有反向解包逻辑。

修改方向：对外直接返回 A/B/C/D/E 的结果对象，并与本题磁盘 JSON 回读结果一致；内部如何传递结果可以保留，但必须在 HTTP 边界完成合法解包。`serve_local` 对裸题目的处理不能证明 SDK 生产入口也满足此要求。

证据：[agent.py 第 22 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/agent.py#L22)。

### 3. Single 没有复用已有的派题授权检查

engine.py 第 63–69 行直接 `CaseContext.from_dict(payload)` 并执行题目。models.py 第 24–38 行只检查字段、编号、function 和 schema；没有检查该编号是否属于本次派题、assigned 文件哈希是否等于 dispatch 清单、请求是否与 assigned 八字段完全一致。

代码在 dispatch_plan.py 第 98–108 行已有文件路径和摘要检查，但由 batch/precheck 的 `load_dispatch` 触发，正常 Single 路径没有调用它。批量预检查存在不能替代每次线上单题入口校验。修复时只读取当前 assigned，不能为了验证当前题读取所有其他题正文。

证据：[engine.py 第 63 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/src/research_agent/core/engine.py#L63)、[dispatch_plan.py 第 98 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/src/research_agent/core/dispatch_plan.py#L98)。

### 4. 网关会话头缺失，SDK 的网络关联头不是替代品

llm.py 第 185–187 行创建 OpenAI 客户端时没有设置 `X-Session-ID`；标准库后备通道第 205 行也只有 Authorization 和 Content-Type。此提交自有源码没有读取 `CHALLENGE_SESSION_ID`。

同时核对本地 SDK 1.1.1 参考源码：`network.py:45` 的注入逻辑写入 `x-agenthack-session-id` 和网络追踪头，**不是**组委会要求的 `X-Session-ID`；其 telemetry session 缺失时生成本地随机 ID，也不读取 CHALLENGE_SESSION_ID。不能因为启用了 SDK 拦截器就认定已满足网关会话要求。

修改方向：对 OpenAI 和后备通道统一显式设置 `X-Session-ID: CHALLENGE_SESSION_ID`，正式模式缺失时给出可定位的失败。该标识不同于 case_id 和传输 UUID。

证据：[llm.py 第 185 行](https://github.com/Sunming1126/research-agent/blob/7ceaaa21956b9bb5b56758efa608cb1b2989b553/src/research_agent/integrations/llm.py#L185)。
