## 同一原生对话中的执行顺序

所有功能、数据与模型测试继续通过既有 Agent挑战赛工作区及固定主对话执行，连接为 magic。不能直接在其他终端启动这些阶段来绕过会话归属或原生审批。

1. `baseline`：对 main `64f5efd` 的不可变快照执行七项冻结契约反例，原始失败全部保留。
2. `regression`：对当前候选执行 tests 与 evaluation，1 CPU、1 GiB、只读代码、禁网。逐项记录失败和条件跳过。
3. `build`：仅当相同源码指纹已通过回归且工作区已提交时构建，核对 Linux amd64、非 root、非空凭据环境和实际源码身份。
4. `acceptance`：先以模拟网关验证超时、非法 JSON、账户额度拒绝与迟到结果；再以当前 magic 接口执行公开 11 题及独立 D 重复轮。检查真实 HTTP 最外层、assigned、落盘、计量、实际 OTLP 关联及 PDF 物理页摘录。
5. `archive`：仅允许与已通过本地验收的不可变镜像 ID 对应。导出小于 2 GB 的 tar，检查归档配置摘要与标签，重新导入同 ID，在新只读容器检查健康，附源码、SHA-256 和交付清单。不操作赛事上传或启动评测。

每一阶段由原生工具执行 `镜像测试/native_main_contract_run.py --stage <阶段>`。协调器检查本次阶段对应的新原生工具记录；固定目录冲突不会被覆盖。原生 Docker 权限仍由用户处理。
