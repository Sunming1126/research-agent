# R2：正式分题限时兼容闭环

2026-11-02。仅处理限时这一因素；比较基线固定为已提交 R1 的 `08b28f01bfe759dc3d7bd1d46d026bbd87005878`。没有同时调整检索、报告内容、D 算法、选参或 wall-clock 选路阈值。候选等待评审及真实环境 canary，不直接覆盖队友版本。

## 观察—假设—实验—结论—决策

**观察。** 起点默认单题 180 秒，engine 和官方运行时 HTTP 适配层另行硬限 180 秒；D 正式客户端子进程还限 175 秒。即使单独扩配置，仍无法使用用户给出的 A/B540、C/E900、D1800 秒正式额度。SDK 继续由未修改的 `AgentRuntime(ResearchAgent()).run()` 启动。

**假设。** 同步内外层限时，并让 D 正式子进程受统一剩余预算约束，能消除确定的提前取消风险；它并不能证明模型内容更准确或 D05 零分已修复。

**实现。** 独立 `core/time_limits.py` 按已校验 function 给出上限；设置默认值为最大题型额度 1800，实际仍逐题压到对应上限。显式较小配置优先，示例配置同步默认值。engine 保留最多 10 秒用于落盘/SDK 导出，排队仍消耗同一预算；D 子进程取当前剩余预算并保留 5 秒。SDK 的 TaskConstraints、Gateway 单题 deadline 及取消机制继续生效。无效题型保持保守边界，仍由原请求校验报告错误。

| 题型 | HTTP/SDK 最大秒数 | engine 内部秒数（默认） |
| --- | ---: | ---: |
| A/B | 540 | 530 |
| C/E | 900 | 890 |
| D | 1800 | 1790 |

30 次调用、40000 Token 上限以及各模型请求阶段 cap 不扩。实际调用数、耗时与 Token 是否变化仍待真实模型测试；给予更长截止预算不代表自动消耗满额。

**实验。** 33 项固定合成用例，顺序旧→新→新→旧→旧→新，各版本 3 次。包含各题型默认/显式较小/过大配置，HTTP 传入 SDK 的约束、虚拟时间跨越旧 180 秒边界、真实截止及取消拒绝，以及 D 客户端使用剩余预算。测试使用假响应和可控时钟，不等待 1800 秒、不执行隐藏实验或外连模型。

原 Harness 固定工作区/总控原生执行以上 R2 对照、全量及 SDK，目标模型 0 次。唯一全量失败仍为已经在未改动队友版本重放确认的 Windows 授权绝对路径问题，未忽略或标绿。新增 33 项不能被当作 33 题正式判分。

**结论。** 同例连续重复支持限时契约修复，未出现该组测试的选择性成功。正式输入不一致、模型内容、D wall-clock 选路、实验分数方差和长任务内存稳定性没有因此得到验证。尤其较长预算会改变 D 既有依余量决策所处的条件，虽然该算法/阈值源码未改，仍须真实 canary 验证后决定是否采用。

**决策。** 单独保留 R2 提交供评审，可独立撤回或仅采用 R1；不自动合并到队友分支或上传镜像。P0 整体稳定性验收仍未完成，不能进入未经评审的 D 算法重构或 B 内容策略优化。

## 失败记录与证据链

首次批次的旧版 33 项确已执行，结果 10 通过/23 失败；父协调器读取子进程 GBK 输出时按 UTF-8 解码失败，后续未执行。保留原始 stdout、stderr、已完成旧版结果和批次失败标记。修复为子进程显式 `-X utf8`，使用新的原生请求及批准重跑；没有用替换字符掩盖损坏 JSON。随后一次窗口焦点校验失败，未输入、未发出测试；恢复经前台句柄与编辑器双重核验后再发送。
