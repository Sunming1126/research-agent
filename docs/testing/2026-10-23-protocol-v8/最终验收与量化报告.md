# 平台422修复与v8本地验收

原422根因：生产SDK要求包装任务，而平台直接发送八字段题目。验证阶段就拒绝请求，所以截图显示模型调用/Token/模型耗时为0。不是上传包体积问题，也不是模型回答质量问题。

v8适配生产HTTP入口，直接题目通过原SDK执行，再返回题目要求的结果JSON。旧SDK包装格式、官方遥测与模型拦截、traceparent、取消和健康接口保留。新增三种拒绝重试边界与精确状态/时间反馈，由模型返回完整修复源码，没有手改生成算法或评分结果。

v7主轮127PASS/1FAIL/1官方BLOCKED、独立D轮21PASS，唯一失败是拒绝后未在同服务器同一时刻重试。不同模型源码的重复轮通过不能抹去原失败。v8冻结原始错误源码，补deadline/horizon/连续拒绝三探针，检查状态、顺序、即时派发时间与服务器状态；D05内部探针由9增至12。
