# 固定主线与局部优化的采纳约定

2026-10-29 用户确认：实验后如果旧版更适配，就换回旧版对应方案；确定大方向后，不反复进行大方向改动。该约定适用于后续优化，不改变已有工作区、模型连接、授权材料或凭据隔离规则。

## 当前固定主线

授权材料检索 → 原文证据核验 → 生成 → 校验落盘。沿用现有官方运行时和 A–E 工作流，优先处理已观察到的可靠性问题。0.4.17 / a329dd6 作为对照基线，0.4.18 / 43f8189 的生产源码作为实验候选；二者都没有本轮 Linux 新镜像验收结论。

本次只记录方向、复盘既有证据和准备对照协议，不修改生产源码，不生成新镜像，不把复盘当作新测试。后续局部改动必须先通过协议，才能成为推荐版本。

## 先澄清上一轮差异

既有真实模型规则检查旧版10/10、新版9/10，B为6/6对5/6；这是本次观察到的表现下降，失败保留。

本次静态复核确认：B 的 tasks、retrieval、evidence_selection、paper_selection 文件在两侧完全相同；深页 probe 函数在预算输入保护之后的 AST 也相同。0.4.18 增加非法/非有限预算保护，未改变有效预算下的检索主体。因此上一轮不是两种不同 B 检索架构的有效对照，不能直接据此选择新检索方向，也不能据此免除新版漏答问题。

首轮 B-44 候选扫描538页、打开42/60篇，旧版扫描752页、打开53/60篇，两侧均达到约12秒扫描上限，使用的模型查询计划不同。后续交替诊断双方9/10，均漏B-50。来源哈希、代码检查及既有记录摘录见 `方向核对-静态与既有日志.json`。

这些是静态检查和已有记录复盘，目标模型新增调用0，不是新的配对试验，也不能证明新旧性能相等。共享模块导入、模型改写、负载、缓存和扫描顺序等因素尚未隔离。

## 下一步对照协议

1. 先做无模型的检索通路对照。冻结相同论文、题目和查询计划，把查询改写从变量中移除；新旧使用相同预算，按AB/BA交替顺序至少重复三组。记录冷/热缓存状态、扫描页数、打开文档数、停止原因、墙钟/CPU时间和结果文件集合。全程从原 Harness 固定总控原生工具发起。
2. 再分别重放首轮旧/新查询计划，固定源码版本，检验查询改写对排序和预算覆盖的影响。不能同时修改排序、配额、阈值和时限；每项只做一个因素。
3. 只有定位后，才制作一项局部修复。比较集包括既有失败题、稳定参考题及提前冻结的未用于调参题，含明确的无匹配反例。保留所有轮次，不因失败重新命名、删题或改标签。
4. 局部检索改善后，再在原 magic 连接做冻结 A–E 新旧交替真实生成对照。B 记录逐题正确文件集合、漏答与误报；C/E 分开记录格式、事实支持和评估器失败；D 的材料缺失控制不能代替正式算法实验。

三组重复仅作为工程诊断，不足以据此宣称统计显著或总体准确率。无原生执行证明、因额度/权限/窗口状态未执行或中断的项目均单列，不算通过。

## 采用与撤回

- 用户进一步确认：正确率第一，包含漏答、误报和事实支持；耗时和Token同样记录。正确率不下降时优先更快、更省；若更高成本换来可重复的正确率提升，需并列报告代价与收益，不用省时、省Token抵消正确率下降。
- 证据不足或结果不稳定，保留旧基线，不提升候选版本。
- 重复对照显示局部新方案在正确性、误报或稳定性上更差，则撤回对应改动；若新方案正确性不降、在预先约定的目标上有可重复收益，才考虑采纳。
- 较低Token或较快耗时不能抵消漏答/伪造；不得只凭更高总分遮蔽某类任务的明显下降。任何速度/消费权衡须写明。
- 引用/追溯修复与B检索分开评估。优先保留已验证有效且无回归的独立修复，不因一个模块失利盲目整包回退；若修复本身引入问题，也应撤回。
- 不因新论文、新项目或版本号反复更换主线。后续资料仅用于解决明确局部问题。源码、证据与未解决问题及时同步协作分支，保持main和队友代码完整。

正式镜像推荐仍须补齐 Linux / 1CPU / 1GiB / 官方HTTP与OTLP验收，源码检查不能替代。
