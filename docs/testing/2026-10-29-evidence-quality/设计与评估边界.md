# 跨任务证据质量与资源可靠性

本轮基线为 a329dd6（0.4.17 / PR #9），分支 improve/evidence-runtime-quality-20261029。当前仍为自我优化，不合 main、不上传赛事。论文级研究需要明确任务、冻结数据、对照/消融、逐项证据和失败分析；本轮不会把工程检查通过称为已经达到论文级智能。

## 源码审查确认的风险

1. 最终格式校验接受 `[1,2]` 和 `[1,2,p.4]`，但报告审查/修订上下文的旧解析只识别单篇引用。模型漏报 used ID 时，可能漏送实际引用的来源；有时则回退发送无关论文。新实现共用同一引用语法，引用分组、页码、归因和修订定位保持一致。
2. 旧同页摘录恢复会把所有已召回片段直接拼起来：缺失的中间正文、不同文件内容哈希及重复重叠都可能形成并非原文的摘录。新实现同页/同文件内容哈希成链，核对重叠一致性、合并真实重叠，超过段间边界的缺口不跨越。段间最多三个字符的容差来自本项目 Chunker 的双换行分隔与边缘空白；它不允许跳过非空中间段落。单片段匹配仍保留原校验。
3. B 旧探查按篇平均页数分配预算，短论文用不完的额度没有交给长论文。本轮试验了读取页数后按 max-min 公平重分配的版本；顺序大库对照中主诊断旧版10/10、平均额度消融9/10、重分配7/10，后两组频繁触及12秒上限，存在主机负载和固定顺序干扰，不能简单认定全部差异由算法导致。这项试验未通过采纳门槛，已从生产候选撤下，保留原有B策略。其配额缺陷继续以strict xfail保留，不算通过。只采纳非法/非有限预算的输入保护。

本轮不修改官方入口、SDK 适配、生产依赖或 D 算法。原子发布、失败不覆盖成功、来源授权等已有保护继续回归。

## 一手研究依据及实际采用范围

- [ALCE 论文](https://arxiv.org/abs/2305.14627)、[作者评估代码](https://github.com/princeton-nlp/ALCE/blob/main/eval.py)：读取官方摘要和引用评估实现。借鉴将内容正确性与引用质量区分的评估方式；没有安装或复现其完整基准/模型。
- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)：读取正式摘要；将报告拆成可核验事实，而非只看整篇单个 ok 标志。本轮不是该论文人物传记基准的复现，不引用其成绩为本系统成绩。
- [SAFE / LongFact 论文](https://arxiv.org/abs/2403.18802)、[作者代码仓库](https://github.com/google-deepmind/long-form-factuality)：读取官方摘要和仓库说明；借鉴生成与核查分开的流程。SAFE 原方法含网络搜索，本系统只允许当题授权材料，故不用网络搜索替代指定论文。曾尝试读取 atomic_fact_generator.py 链接未成功，不冒称读过该文件。

这些方法支持可核验的研究设计，但不能证明本实现正确。具体修复只由不变反例、完整回归、冻结真实材料和实际输出支持。

## 本轮验证约定

- 0.4.17 从已发布源码 ZIP 按 SHA256 冻结，反例在每次原生运行时复制并记录哈希，两侧使用同一份文件。
- B 使用上一轮 60 篇/1,425 页的同一冻结语料和题目，不改标签；保留“恢复平均页额度”的消融失败，生产候选回到旧策略。后续按题交替旧/新顺序做复核；不把主机时段差异直接当作因果结论。
- A–E 真实模型对照使用提前冻结的本地问题。A 为小型数学/字段控制；D 只验证缺少实验会话时诚实失败，不代表 D 算法得分。
- C/E 另外用独立提示核查报告中的论文事实，不传入生成器自审结论。核查由相同 provider 的模型执行，每篇最多抽查十二项、来源也按预算截取；它不是独立人工金标或完整报告事实正确率。
- 对 supported/contradicted 判定，程序还校验句子来自报告、来源 ID 合法、quote 真正在给定摘录中。摘录存在依然不能自动证明语义蕴含，需要保留核查理由及人工复核。
- “未在给定摘录找到依据”与“论文明确反驳”分开；拟议实验参数与论文已完成结果分开。任何失败、额度中断、未知用量及未执行项均保留。
- 目标生成调用、评估调用、Harness 总控协调消费分别统计。只有 Windows 源码/引擎结果时，不当作 Linux 1CPU/1GiB、正式 HTTP/OTLP 或新镜像合格结论。

后续结果另见本目录验收报告与机器统计。资料在 Git 中只公开必要元数据、响应、trace 和哈希；完整请求与原始论文留在本机及 D 盘，不发布凭据。
