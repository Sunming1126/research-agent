# 0.4.18 引用与原文追溯优化验收

本轮基于 0.4.17 / a329dd6，在独立分支 `improve/evidence-runtime-quality-20261029` 完成。可以确认引用处理和摘录追溯的工程修复；不能确认整体回答质量、B 检索稳定性或官方成绩提升。当前为供队友审阅的源码候选，尚不具备新镜像验收结论。

## 修复了什么

1. 统一引用语法。最终校验、事实审查、局部修订及方法归因均识别 `[1,2]`、`[1,2,p.4]`；防止漏送被引用论文、混入无关来源或跳过分组引用中的错误归因。`[111]` 晶向仍不当作论文引用。
2. 收紧原文摘录拼接。同文件名和页码还必须具有相同文档哈希，不能跳过缺失正文，重叠文字必须一致，真实跨块摘录只保留一次重叠。减少“每个词都在原文，但整句话从未出现”的错误证明。
3. 拒绝非法或非有限的深页扫描预算，避免 NaN/Infinity 等使资源限制失效。有效预算下保留 0.4.17 的 B 探查策略。

没有修改官方入口、SDK 适配、生产依赖或 D 算法。静态入口仍由 Docker `python agent.py` 启动，实例化官方 `AgentRuntime(ResearchAgent())` 并最终 `runtime.run()`；不把这项静态核查称为容器或平台验收。

## 源码回归与已知缺陷

测试均从用户指定的原 DeepSeek Harness 工作区/总控对话原生工具发起；固定会话 `session-9c903d0e-5884-44fe-bc7f-3719da00864b`。源码冻结快照、同一份反例的 SHA256、JUnit 和启动错误全部保存。

| 检查 | 0.4.17 | 0.4.18 最终候选 |
|---|---:|---:|
| 引用/来源追溯反例 | 0 通过、13 失败 | 13 通过、0 失败 |
| 页预算未充分分配缺陷 | 1 项已知 xfail | 仍为 1 项已知 xfail |
| 最终全套源码回归 | 本轮没有重跑旧版全套 | 387 通过、0 意外失败、6 环境跳过、1 已知 xfail |

最终收集 394 项。按全部收集项计算，明确通过占 387/394（98.22%）；跳过和 xfail 均不算通过。针对本轮列出的 14 项缺陷，修复 13/14（92.86%）；其中引用/追溯专项 13/13。此比例不代表所有历史缺陷、隐藏题或线上事故拦截率。

最终源码 193 个 Python 文件与回归、真实生成和交替检索时的 SHA256 一致，具体指纹见 `metrics.json`。旧版十三项均为断言失败、没有导入错误；夹具修正前的 setup 错误、沙箱临时目录拒绝访问及中间候选结果全部保留，不用最终结果覆盖。

## 真实模型 A–E 对照

在原工作区、原总控对话使用既有 magic / deepseek-v4.1-flash。提前冻结 10 道自拟题，两版本共 20 次任务执行；生成器看不到评估端的 source_facts。B 为六题，其余 A/C/D/E 各一题。本轮不是官方 11 题或 25 题全量评测。

| 指标 | 0.4.17 | 0.4.18 |
|---|---:|---:|
| 执行完成且答卷与磁盘一致 | 10/10 | 10/10 |
| 自拟规则检查（含 B 文件命中） | 10/10 | 9/10 |
| B 正确文件集合 | 6/6 | 5/6 |
| A 小型数值/澄清控制 | 1/1 | 1/1 |
| C/E 格式及落盘 | 各 1/1 | 各 1/1 |
| D 缺少实验材料时诚实返回 | 1/1，0 模型调用 | 1/1，0 模型调用 |
| 生成调用 / Token | 25 / 99,615 | 24 / 96,977 |

不能据此声称 C/E 事实全部正确，D 也没有完成正式算法实验。少一次调用和较低 Token 不能独立归因为优化收益，样本小且执行路径不同。

首轮候选 B-44 漏答保留为失败：旧版扫描 752 页，新版 538 页，均触及约 12 秒上限；模型生成的查询词不同，探查排序使用全部查询词作盐，改变文档顺序。这是时间预算、主机负载和模型查询变化共同影响的证据，尚不是因果隔离实验。生产代码在有效预算下沿用旧策略，不能据此断言新引用代码造成漏答，也不能把漏答删除。

随后对同一批 60 篇 / 1,425 页公开论文的十道既有字面深页诊断，按题交替新旧执行顺序、每题启动新进程，双方均 9/10，均漏 B-50。失败时候选只打开 28/60 篇、旧版 21/60 篇，分别扫描 418/311 页后达到 12 秒上限。诊断使用确定性模拟读者，不调用目标模型，测的是召回通路而非模型理解。不是随机留出集，也未控制主机负载，故不报显著性或总体检索准确率。

一次额外 B-44 配对复测尝试未收到原 Harness 原生消息确认，随后前台焦点核验失败；该尝试没有发出目标模型请求，记为未执行。没有另建工作区或改用独立后台模型测试，也不虚构补测通过。

## 未采纳的页分配实验

试验曾先读各篇页数，再把短论文用不完的额度按 max-min 方式重新分配。固定顺序的大库诊断旧版 10/10、恢复平均额度的消融 9/10、重分配原型 7/10，后两组多次超时。存在时段/负载和固定顺序干扰，不能把差异全部归因为分配算法。

原型未通过采纳门槛，已从生产候选撤下。原型以 `.py.txt` 保存并记录 SHA256；当时源码快照和所有失败均保留。最终保留原 B 策略及 1 项 strict xfail，明确承认短论文页预算未充分再利用仍未解决。

## C/E 额外事实核查的结果与局限

借鉴 ALCE、FActScore、SAFE 的评估思路，另外用独立提示、同 provider 模型核查报告，不把生成器自审结论当独立证据。只依据授权来源摘录，每篇最多五条、每份报告最多十二项；核查句子必须来自报告，支持/反驳引用必须是给定摘录中的连续原文。具体读取范围及原始论文链接见 `设计与评估边界.md`。

首次 4 份报告仅 1 份通过评估输出契约：另三份超出条数或拼接非连续摘录。对失败输出只允许一次带客观错误反馈的修正，保留报告与原始来源。修正后共 3/4 份完成评估，候选 C-21 仍超出十二项，继续标记失败。不能事后截断它再宣称通过。

| 报告 | 最终严格核查状态 | 抽样结果：支持 / 反驳 / 摘录未覆盖 / 不确定 |
|---|---|---|
| 旧 C-21 | 格式修正后完成 | 1 / 0 / 1 / 10 |
| 新 C-21 | 评估失败，条数超限 | 不计算通过率 |
| 旧 E-21 | 首次完成 | 7 / 0 / 5 / 0 |
| 新 E-21 | 格式修正后完成 | 6 / 0 / 3 / 3 |

这些不是事实准确率，也不能横向直接排名。每份来源按预算截取，某些被报告引用的页没有进入评估摘录；一条长句又含多项事实，不够原子化。旧评估输出还出现 verdict 为 supported、理由却称整体应判 uncertain 的自相矛盾。程序对 JSON、句子和引用存在的校验不能证明语义蕴含；Codex 的补充审阅也不是人类专家标注。

明确需要继续核实的候选表述包括 RETRO“检索开销随检索数据量线性”的复杂度范围，以及 E 中收益假设、等效界和停止判据的一致性。当前摘录只能支持 token 块检索减少计算等更窄结论，不能把这些更广的表述签为正确。拟议参数已经标注待验证，不是本次实测。没有发现可用于宣布整篇事实正确的充分证据。
