# 0.4.17：正文深页补召回与证据留存

本轮确认了一个可修复的 B 类漏检原因：旧版只读每篇前几页，再深入排名靠前的论文。关键条件只在后文出现时，论文可能根本进不了补读名单。新版增加有页数、时间和模型余量限制的授权正文探查，并保存获准原文片段，修复了这条路径。

本轮交付是**经过 Windows 源码验证的候选**，不是新 Docker 镜像或正式赛题分数。分支 `improve/b-depth-coverage-20261029`，基于 `b472c173334f68a2e6ca80568902f98aee3443b1`（0.4.16 / PR #8），不合 main、不上传比赛。研究依据与方案选择见[方法依据与验证设计](方法依据与验证设计.md)。

## 真实材料与标签质量

本机新增下载 52 篇，加原有 8 篇材料，共 **60 篇、1,425 页、9 个分类**。逐篇核对 SHA256、标题、未加密、全文可解析性；60/60 通过，无排除项。分类及来源见 [corpus.json](corpus.json)，含 arXiv 原始论文和作者大学网站公开综述。下载原文不等于已经通读或完成学术同行评审。

历史 100/300 篇 manifest 不代表本机当前已有对应 PDF。60 篇中有部分按历史文件大小优先补齐，属于跨领域诊断库，不代表自然论文长度或学科分布。原 PDF、完整模型请求和缓存只在本机/D 盘保留，Git 与 Docker 不包含这批 PDF。

自动题目曾暴露标签错误，本轮没有隐去：

- v1 会丢失字体连字，还会删除表格数字后拼接词语，以及把参考文献误当正文；其原始运行保留，整体不作主结论。
- v2 修正为 Unicode NFKC、真实换行断词处理和连续词校验。人工只看原文、尚未查看 v2 检索结果和调用目标模型时，又排除了 B-48 的表格列标题和 B-49 的资助致谢，两版对称排除。审计时间与理由见 [label-audit-v2.json](label-audit-v2.json)。
- v2 全部 12 条原始结果仍公开。主统计使用审计后 10 条，开发/留出各 5 条；真实模型使用其中四道合格留出题，并增加四道已知参考题和两道原始方法语义题。实际派给测试引擎的冻结清单见 [benchmark-v3-audited.json](benchmark-v3-audited.json)。

这类精确短语任务刻意考查深页覆盖，不能代表一般语义科研检索。两道新原始方法题按官方 CRAG/HyDE 论文摘要设定，不是独立官方金标。单轮、小样本、同一模型的观察，不能换算成官方 B 类得分或保证隐藏题满分。

## 修改范围与限制

正文探查只读取 `DocumentIndex.materials` 内当题已授权的 PDF。默认最多 1,200 页、12 秒，每篇最多保留两页，并为模型处理保留 95 秒；取消和超时继续传播。超长文档按页均匀抽样，预算未覆盖之处记录 `coverage_limited`，B 内部诊断标为 partial，不把有限覆盖的空结果视为穷尽整库后的不存在。

页数预算按文档分配，尚有改进分配利用率的空间；时间上限是在页/文档之间检查，单次底层 PDF 解码不具备硬实时中断保证。即使所有页都扫描过，也只有部分原文进入模型，因此不承诺语义检索零漏检。参考文献检测在不规范 PDF 上也仍有限；本轮标签审计正暴露了这点。

新增片段留存包含获准的真实 Chunk、物理页码、论文/片段哈希，内部可以核对批准原因。最初实现额外要求检索器 `.chunks` 属性，导致 39 项旧接口回归；已改为使用检索阶段实际返回的来源对象，没有修改旧测试断言。

官方 `agent.py`、AgentRuntime 启动、SDK 适配器、生产依赖及 D 算法相对基线不变。6 项跳过涉及 Windows 符号链接/文件名限制、Unix 官方客户端流程及未安装的原 300 篇专用夹具，均未冒充通过。

## 原始失败、复现与交接

- 两次早期下载共 154 次 URLError。随后独立诊断定位到证书签发链缺失，补充本机已有 certifi 公共根证书后下载成功；始终开启证书和域名验证，没有改系统信任或关闭 TLS 校验。
- 第一轮反例夹具把材料根配置为工作区根，5+5 条失败；已修正独立材料目录，同一修正后的文件分别运行旧/新版本。
- 首轮受限完整回归 198 通过、66 失败、105 错误、2 跳过。其中 132 项错误/失败带 PermissionError，39 项为新增检索器属性兼容回归，不能全部归咎环境。最终批准环境重跑 365 通过、0 失败、6 跳过。
- 首次大库核验缺少离线工具初始化且没有及时落盘逐篇排除原因，未达到门槛，不构成论文不合格证据。修正本地源码检查环境并补逐篇诊断后，60 篇通过。不能事后为那次未记录的逐篇失败编造确定原因。

详细机器统计见 [metrics.json](metrics.json)；原生执行归属、JUnit、旧版失败、新版结果、两批标签诊断和真实响应位于 `evidence/`，逐文件哈希见 [evidence-sha256.json](evidence-sha256.json)。完整请求仅公开哈希；带原文的内部证据只公开 trace 与原始文件哈希。所有失败原样保留。

所有测试均由已有“Agent挑战赛”工作区的原生工具执行，固定总控 `session-9c903d0e-5884-44fe-bc7f-3719da00864b`，没有新增工作区或独立 headless 模型任务。复现需在同一原生会话触发 `b_depth_20261029.py`：`--stage regression`、`--stage library-v2`、`--stage live`。冻结资料目录已有时不要直接覆盖重建标签，应使用原冻结文件或新建带版本的运行目录。

Docker 的 Windows 临时通信目录问题仍阻断新容器验收。本轮没有新 tar，没有 Linux 1CPU/1GiB、正式 health/solve、正式 OTLP 或 tar 重载结论。当前可交接源码候选与证据；打包/提交前仍需完成这些验收。
