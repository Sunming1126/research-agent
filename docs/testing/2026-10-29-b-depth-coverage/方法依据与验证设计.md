# 正文深页覆盖：依据、选择和验证边界

已完成的实际结果与全部失败说明见[本轮验收与交接](本轮验收与交接.md)；本文记录选择依据和验证设计。

候选基于 b472c17（0.4.16），工作分支 improve/b-depth-coverage-20261029。当前先自我优化，不合 main、不上传比赛。正式入口仍是原官方 AgentRuntime；依赖和 D 算法不作改动。

## 已定位的实际问题

旧 B 流程按库规模只索引每篇前 2/4/8 页，再完整读取进入候选列表的最多八篇论文。关键条件仅在深页出现、且初始页没有足够相关词时，该论文无法进入完整读取的名单。前页筛选造成的覆盖空洞，不能通过增加大模型判断次数弥补。

新方案在查询规划后，依据题面及查询计划，对当前题已经授权的 PDF 补做一次原文页探查，再复用原有检索融合、候选全文扩展和逐篇模型核验。每题最多探查 1200 页、12 秒，并预留 95 秒模型处理时间；按文档分配页数，超长文档均匀抽样。只保留每篇最多两页的原文片段，不创建全局知识库或引入向量模型。达到上限或 PDF 失败时记录 coverage_limited；不把有限覆盖下的空结果宣称为穷尽整库后不存在。

这不是严格硬实时保证：单次本地 PDF 解码仍是同步调用；时间上限在页与文档边界检查。Windows 主机测量也不等于 Linux 1 CPU/1 GiB 验收。

## 本轮核验过的一手资料

- [CRAG 原论文](https://arxiv.org/abs/2401.15884)：读取官方摘要、版本信息；借鉴根据检索质量采取修复动作的原则。本文没有复现其评价器，也没有引入论文中的网络检索。赛题运行时只能读取当题授权材料。
- [FLARE 原论文](https://arxiv.org/abs/2305.06983)：读取官方摘要、版本信息；支持显式考虑何时、检索什么。本文不采用生成词概率触发机制，没有声称复现 FLARE。
- [Haystack AutoMergingRetriever 官方实现](https://github.com/deepset-ai/haystack/blob/main/haystack/components/retrievers/auto_merging_retriever.py)：阅读父子文档合并机制。已有候选全文扩展继续承担上下文补全；不直接引入整个框架或替换现有索引。
- [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)：官方摘要指出长输入中位置会影响取用信息的表现。它研究的是模型上下文利用，不是本项目已证实的“初始 PDF 没读到深页”同一故障；这里仅作为控制输入长度的旁证，不能拿论文结论代替本项目实测。
- [HyDE 原论文](https://arxiv.org/abs/2212.10496)与 [RAG 综述](https://arxiv.org/abs/2312.10997)：核对官方元数据。HyDE 需要额外生成和编码环节，本轮暂不引入；资料下载后是否通过全文核验，以 corpus.json 为准。下载全文不等于已经通读全文。
- [BRIGHT 原论文](https://arxiv.org/abs/2407.12883)及 [作者代码](https://github.com/xlang-ai/BRIGHT)：读取官方摘要和项目说明。它区分词面/主题相似与需要推理才能确认的相关性，提醒本轮连续短语测试只能证明覆盖路径。故真实对照还加入新公开方法的原始贡献判断和旧题回归，分别统计；并未运行 BRIGHT 全数据集，不引用其分数为本项目性能。

## 冻结验证的安排

1. 对原始 PDF 核对来源、SHA256、可解析性、实际页数和首页标题，排除不符材料。历史 100/300 篇清单不算当前机器上已经验证过的 PDF 库。
2. 用不变的合成 PDF 反例分别测试冻结旧版和候选，确定深页信息能否送到读者；确定性读者只验证工程路径，不代表大模型准确率。
3. 从真实论文第八页以后生成唯一连续短语，先固定题目和文档互斥的开发/留出划分，再测两个版本。该诊断特意考查深页词面覆盖，不是随机科研需求分布或官方隐藏题。
4. 真实大模型对照与离线模拟分开统计；固定已有 Harness 工作区/总控和 magic，标签不传入生产代码或模型。
5. 公开必要元数据、响应、源代码摘要和失败证据；完整模型请求及 PDF 缓存仅保存在本地/D 盘，不随 Git 或镜像发布。

结果尚未产生时不写通过率。中间失败、审批阻断、用量未知分别保留；只有已完成的有效运行进入相应统计。
