# 原生运行时响应与默认论文库修复

版本：`0.4.3-runtime-20261024`。关联评测：`eval-20261024-486e8a18`，以及用户补充的 A 协议有效、B-01 失败截图。平台未提供详细容器日志，因此本地缺口与线上根因仍需区分。

## 已复现的旧版缺口

用旧 0.4.2 镜像，在只读 `/data/论文库` 中挂载合成 PDF，仅设置标准 `TEAM_ID`、模型及 OTLP 参数，不提供自定义 `RESEARCH_*` 配置：

- A-05 返回 200，调用模拟网关一次；响应没有 SDK `metadata`。
- B-01 使用规范中的 `本地论文文件夹内的 PDF` 描述，模型调用 0 次，报 `MaterialError: authorized material not found`，被适配路由改成 HTTP 500，响应也没有 SDK `metadata`。
- 本地 OTLP 仍收到这两次任务的实际追踪，说明不能由“模型 0 次”断定 SDK 完全没运行。平台的追踪关联失败原因尚不能只凭页面确定。

旧版默认材料根目录为空；上一轮成功的 B 测试通过额外指定测试目录绕过了该默认配置缺口。剥离 SDK metadata 又丢失了响应中可供关联的 trace/session 信息；它是否为平台追踪缺失的直接原因，仍待官方环境验证。

## 修改

1. 主入口直接构造官方 `AgentRuntime(ResearchAgent())` 并执行其 `run()`。CLI 的 serve 入口相同。缺少官方 SDK 时拒绝启动，不再自动降级成独立 HTTP 服务；离线 HTTP 服务移入测试夹具，不进入参赛镜像。
2. 通过原生 FastAPI 应用的请求中间件，把八字段输入转为 SDK 支持的包装格式。没有继承 AgentRuntime、替换路由、调用私有路由端点或修改 SDK。
3. SDK 的成功、error、timeout 响应均原样透传，保留 `task_id/status/output/metadata`。题型 JSON 仍放在 SDK 原生 `output.answer`，磁盘按原始题型格式保存。不额外生成追踪，不伪造成功。
4. 未显式配置材料根目录时，使用标准专用 `data/论文库`。默认 `/data` 挂载根对应 `/data/论文库`，支持规范中的整体检索描述，以及 `data/论文库/<文件名>` 路径。显式配置（包括显式空列表）优先；不搜索其他队伍、整个工作区或输出目录，也不将指定领域的模糊 C/E 描述扩大成全库权限。
5. 未显式配置本队目录时使用平台 `TEAM_ID`，避免把结果写到本地示例的 workspace_team。材料错误记录类型、根目录和诊断文件位置，不记录模型 Key 或完整请求。

## 验证

9 项原生运行时接口测试通过：实例类型确为 SDK AgentRuntime，health/solve 端点仍属于 `agenthack.runtime`；metadata 的 trace_id/session_id 与实际追踪一致；旧包装、超时、错误、非法输入及原生 JSON 校验保持。

46 项默认目录/授权/核心/架构/网关测试通过，3 项缺少实验挂载跳过。覆盖标准根与项目根两种布局、显式配置优先、TEAM_ID（含基础镜像的空默认值）、空目录配置、拒绝符号链接和越权文件。与 9 项 SDK 测试合计 55 项；离线 HTTP 夹具迁移后另行复测原 HTTP 核心用例通过。

在相同只读标准论文库、无自定义 RESEARCH 配置的 1 CPU / 1 GiB 容器内：A-05、B-01（整体检索描述）、B-02（明确路径）、D-01（材料缺失答卷）及旧包装 A-06 成功；故意缺文件的 B-03 保留 SDK error 和真实失败追踪。六次均保留 metadata，其 trace_id 与实际收到的 OTLP 一致。模型与 PDF 为合成测试夹具，未使用真实 Key。

结果与旧版对照、SDK 哈希核验、原始接收追踪及 tar 清单位于 `team_share/releases/0.4.3-runtime-20261024/`。本地验证不证明官方已接收、已判定入口合规或已产生分数；若仍失败，需要官方用评测编号核对实际挂载、注入参数、原始响应及收集端记录。
