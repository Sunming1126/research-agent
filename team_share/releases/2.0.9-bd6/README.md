# 2.0.9-bd6：原题驱动补检与当轮实验修订

本轮按要求先处理 B，再处理 D。A/C/E、公共模型网关、HTTP 协议、总时间与累计 Token 策略均未修改。没有提交官方测评，也没有推送远端。

## 已知事实与尚未确认的问题

评委已确认 B-02 没有输入输出问题，而是按检索评分规则得到零分。没有该题原始答卷与相关论文集合，不能认定它一定返回了空列表：漏检、误收扣分也可能使结果归零。因此本轮修复能复现的检索缺口，不强行填满答案，也不宣称已消除官方零分。

D 的有效协议不代表方法验收通过。本轮针对当前材料的实现完整性和执行反馈修订，不预装正式题算法，不改写模型生成的源码，不使用隐藏指标驱动重试。

## 公开资料与采用方式

- [FollowIR](https://arxiv.org/abs/2403.15246)：细粒度检索指令与否定条件不能简单视为关键词。保留逐条件核验，空结果时回到原题，防止错误规划持续控制取证。
- [Ai2 Paper Finder](https://allenai.org/blog/paper-finder) 及其[条件相关性实现](https://github.com/allenai/asta-paper-finder/blob/main/agents/mabool/api/mabool/agents/common/computed_fields/relevance.py)：借鉴迭代查询与条件证据核验，加入一次有界补检。不是移植其整套系统，也不是论文保证本项目提分。
- [Self-Debugging](https://arxiv.org/abs/2304.05128) 与 [EvalPlus](https://arxiv.org/abs/2305.01210)：采用执行反例和更有区分度的测试来辅助修订。测试由当轮材料生成；模型测试也可能有错，复核必须先检查期望值是否合法。

没有新装向量模型、外部检索服务或依赖。运行时仍只查当前题授权论文；模型生成的查询只用于找原文，不作为相关性证据。

## B 修改

1. 召回排名仍采用现有词法多路检索与 RRF，但每篇候选的取证范围扩展到该论文当前已索引的全部片段，避免只看关键词命中的背景段落、看不到方法段落。
2. 取证查询不再把排除条件作为正向关键词，从而减少排除对象的背景讨论挤占有效证据。
3. 无批准结果时，以原题片段为边界生成最多六条新查询；不继承可能被加强的必要条件。重新查询后最多补入八篇原候选池外论文。
4. 空结果终审不仅按原题判断，也按原题及新查询选择证据，修复“判断重置了、取证仍受旧规划控制”的不一致。
5. 已成功重规划且没有待恢复的格式/传输问题时，跳过一轮重复的旧条件负例筛选，将时间留给新召回和原题全文终审。

补检有剩余时间门槛；无效改写、模型失败回退原题；未知文件名、伪造证据仍拒绝。真实无匹配题可以合法返回空集合。未增加本地累计 Token 上限，仍受 B 的既有时间控制与平台配额约束。

## D 修改

1. 独立自测从最多三例扩至六例，优先覆盖当轮材料实际定义的不同阶段、参数覆盖、合法边界和多步状态。
2. 生成提示要求完整实现材料定义的分支，明确缺失/null/0/空列表、排序并列与状态污染等通用易错点，不包含具体题算法。
3. 首次修订仍有实际失败用例、且剩余时间充足时，追加最多一次“核对材料与反例—完整生成—同组回测”。没有实际反例、测试隔离不可用或时间不足时不启动。
4. 第二轮候选必须保留所有已通过测试并严格减少失败才采用；超时、异常、无改善、回归都保留第一轮候选，源码与来源响应一起恢复。
5. 保留正式入口、真实失败状态、300 秒正式执行预留和 1800 秒总限时。自测通过不伪装成正式实验通过。
